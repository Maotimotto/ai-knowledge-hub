配置与 Profile 系统

概述

Hermes Agent 的核心配置位于 ~/.hermes/ 目录下。默认 profile 为 default，

所有配置文件、技能、插件、定时任务和记忆都按 profile 隔离。

目录结构

~/.hermes/
├── config.yaml              # 全局主配置文件
├── profiles/
│   ├── default/             # 默认 profile
│   │   ├── skills/          # 技能目录
│   │   ├── plugins/         # 插件目录

Profile 系统详解

创建新 Profile

通过目录结构创建 profile：

mkdir -p ~/.hermes/profiles/work/{skills,plugins,cron,memories}

切换 Profile

在 config.yaml 中修改 default_profile：

default_profile: work

或者通过环境变量临时切换：

export HERMES_PROFILE=work

Profile 隔离说明

组件隔离程度说明
skills完全隔离每个 profile 独立技能集
plugins完全隔离每个 profile 独立插件集
cron完全隔离定时任务按 profile 分组
memories完全隔离记忆数据不跨 profile 共享
config全局共享config.yaml 是全局的

环境变量

Hermes Agent 支持通过环境变量覆盖配置：

# 设置 profile
export HERMES_PROFILE=default

# 覆盖模型
export HERMES_MODEL=gpt-4o-mini

# API Key（优先级高于 config.yaml）
export OPENAI_API_KEY=sk-xxxx
export ANTHROPIC_API_KEY=sk-ant-xxxx

# 日志级别
export HERMES_LOG_LEVEL=debug

# MCP 服务器调试
export MCP_DEBUG=1

# Webchat 端口
export HERMES_WEBCHAT_PORT=3000

    技能 Skill 开发指南

    技能 Skill 开发指南

    🎯 全局定位：Hermes Agent 系列的扩展能力篇。Skill 是 Agent 从"通用助手"进化为"专业工具"的关键机制，通过 Markdown 文件定义行为规范，无需写代码即可扩展 Agent 能力。
    🔗 知识串联：← 上游：01-配置与Profile系统（Skill 目录在 Profile 下）→ 下游：04-MCP-Server-Client实战（Skill 可调用 MCP 工具）、07-最佳实践与调试技巧（Skill 调试与冲突排查）→ 横向：LLM/Embedding与Rerank模型通俗易懂教学指南（Skill 触发本质是意图匹配）
    ⚡ 难度标识：🟡 初级 — 需要了解 YAML 语法和 Markdown 格式，无需编程能力
    🛠️ 落地实践：读完本文后，你应该能独立完成：① 从零创建一个 Skill 目录和 SKILL.md ② 配置 triggers 实现关键词/正则匹配触发 ③ 使用 skill_manage API 运行时管理技能 ④ 编写一个代码审查 Skill 并测试其触发效果

    概述

    Skill 是 Hermes Agent 的扩展能力单元，通过 Markdown 文件定义行为规范。

    当用户的输入匹配 skill 的触发条件时，agent 会加载对应的 SKILL.md 作为

    上下文指令来增强其能力。

    Skill 目录结构

    每个 skill 是一个独立目录，放置在当前 profile 的 skills/ 下：

    ~/.hermes/profiles/default/skills/
├── my-skill/
│   ├── SKILL.md          # 必需：技能定义文件
│   ├── scripts/          # 可选：辅助脚本
│   │   └── process.sh
│   └── templates/        # 可选：模板文件
│       └── output.tpl
├── another-skill/
│   └── SKILL.md
└── ...

    SKILL.md 格式

    SKILL.md 是技能的核心文件，使用 YAML frontmatter + Markdown 正文格式：

    ---
name: my-skill
description: 一句话描述这个技能做什么
triggers:
  - keyword1
  - keyword2
  - "exact phrase match"
  - regex: "^帮我分析.*数据$"
tools:
  - search_files
  - read_file
  - patch
---

# 技能名称

## 能力说明

当用户触发此技能时，你应该：
1. 首先执行某个操作
2. 然后分析结果
3. 最后给出建议

## 操作规范

- 始终使用中文回复
- 输出格式应为 Markdown 表格
- 注意处理文件编码问题

## 示例

用户：帮我分析项目结构
响应：先列出目录树，然后分析各模块职责...

    Frontmatter 字段说明

    字段必需说明
    name是技能唯一标识名
    description是简短描述，用于匹配和展示
    triggers是触发关键词/短语/正则列表
    tools否限制该技能可用的工具列表
    priority否优先级，数字越大越优先（默认 0）
    require_all否是否要求所有 triggers 都匹配（默认 false）

    触发器类型

    triggers:
  # 关键词匹配（不区分大小写）
  - git

  # 精确短语匹配
  - "代码审查"

  # 正则表达式
  - regex: "^帮我.*分析$"
  - regex: "debug|调试|排错"

  # 多关键词组合（全部匹配）
  - and: ["docker", "部署"]

    创建新 Skill

    方法 1：手动创建

    # 创建目录
mkdir -p ~/.hermes/profiles/default/skills/code-review

# 创建 SKILL.md
cat > ~/.hermes/profiles/default/skills/code-review/SKILL.md << 'EOF'
---
name: code-review
description: 代码审查助手，分析代码质量和潜在问题
triggers:
  - "代码审查"
  - "code review"
  - "review code"
  - regex: "帮我看看.*代码"
---

# 代码审查助手

当用户触发此技能时：
1. 使用 search_files 定位目标代码文件
2. 使用 read_file 读取代码内容
3. 从以下维度分析：
   - 代码风格一致性
   - 潜在 bug
   - 性能问题
   - 安全漏洞
4. 输出结构化审查报告
EOF

    方法 2：通过 skill_manage API

    在对话中让 agent 创建：

    用户：帮我创建一个 skill，用于分析 Python 项目的依赖关系

    Agent 会调用 skill_manage 工具完成创建。

    更新技能

  "action": "update",

    技能加载机制

  • 用户发送消息
  • Hermes Agent 扫描所有 SKILL.md 的 triggers
  • 匹配的 skill 按 priority 排序
  • 匹配的 SKILL.md 内容被注入到 agent 上下文
  • Agent 根据 SKILL.md 的指令执行任务
    • 用户输入: "帮我审查这段 Python 代码"
         ↓
匹配 triggers: "代码审查", "code review", regex: "帮我看看.*代码"
         ↓
加载 code-review/SKILL.md 到上下文
         ↓
Agent 按 SKILL.md 指令执行代码审查

    Skill 最佳实践

  • description 写清楚，帮助 agent 理解技能用途
  • triggers 不要太宽泛，避免误触发
  • 每个 skill 专注于单一职责
  • 使用 tools 字段限制可用工具，减少副作用
  • 在 SKILL.md 正文中给出明确的步骤指令
  • 提供示例输入输出，帮助 agent 理解预期行为
  • 避免在 skill 中硬编码路径，使用相对路径或变量

    • 常见问题

    Q: Skill 不触发？

    检查：

  • trigger 关键词是否与用户输入匹配
  • frontmatter 格式是否正确（YAML 语法）
  • SKILL.md 是否在正确路径下
  • 文件是否有 BOM 头（用 file 命令检查）

    • Q: 多个 skill 同时触发？

  • 使用 priority 控制优先级
  • 使用 require_all: true 增加触发精度
  • 使用更精确的 trigger 关键词

    • Q: 如何禁用某个 skill？

    # 重命名目录即可禁用
mv ~/.hermes/profiles/default/skills/my-skill \
   ~/.hermes/profiles/default/skills/my-skill.disabled

    概述

    Hermes Agent 的 Plugin 系统提供了一种结构化的方式来扩展 agent 的能力。

    与 Skill（纯文本指令）不同，Plugin 可以包含可执行代码、工具定义和

    持久化状态，适合更复杂的集成场景。

    Plugin 与 Skill 的区别

    特性SkillPlugin
    定义格式Markdown + YAMLYAML + 可选代码
    复杂度轻量级中等至重量级
    有状态否可以有
    可执行代码否（依赖 agent 工具）是（自带逻辑）
    适用场景行为指令/工作流系统集成/API对接
    隔离性上下文注入独立进程或沙箱运行

    Plugin 目录结构

    ~/.hermes/profiles/default/plugins/
├── my-plugin/
│   ├── plugin.yaml       # 必需：插件元数据与配置
│   ├── handler.py        # 可选：插件处理逻辑
│   ├── requirements.txt  # 可选：Python 依赖
│   ├── tools/            # 可选：自定义工具定义
│   │   └── custom_tool.yaml
│   └── README.md         # 可选：插件文档
├── another-plugin/
│   ├── plugin.yaml
│   └── handler.js
└── ...

    plugin.yaml 格式

    # plugin.yaml - 插件元数据

name: my-plugin
version: "1.0.0"
description: 插件功能描述
author: your-name

# 插件类型
type: tool  # tool | trigger | provider | middleware

# 触发条件（类似 skill）
triggers:
  - "相关关键词"
  - regex: "匹配模式"

# 依赖检查
dependencies:
  python: ">=3.9"
  packages:
    - requests>=2.28.0
    - beautifulsoup4
  commands:
    - curl

# 插件暴露的工具
tools:
  - name: search_web
    description: "搜索网页内容"
    parameters:
      query:
        type: string
        description: "搜索关键词"
        required: true
      max_results:
        type: integer
        description: "最大结果数"
        default: 5

# 插件配置项
config:
  api_key:
    description: "API 密钥"
    required: true
    env_var: MY_PLUGIN_API_KEY
  base_url:
    description: "API 基础 URL"
    default: "https://api.example.com"

# 生命周期钩子
hooks:
  on_load: handler.on_load
  on_trigger: handler.on_trigger
  on_unload: handler.on_unload

# 权限声明
permissions:
  - network
  - filesystem:read
  - execute:local

    插件类型

    1. Tool Plugin（工具插件）

    为 agent 提供新的工具能力：

    name: web-scraper
type: tool
description: 网页抓取工具

tools:
  - name: fetch_page
    description: "获取网页内容"
    parameters:
      url:
        type: string
        required: true
      selector:
        type: string
        description: "CSS 选择器"
        default: "body"

    对应处理逻辑 handler.py：

    import requests
from bs4 import BeautifulSoup

def fetch_page(url, selector="body"):
    """获取并解析网页内容"""
    resp = requests.get(url, timeout=10)

from mcp.types import Tool, TextContent

server = Server("my-server")

@server.list_tools()
async def list_tools():
    return [
        Tool(
            name="my_tool",
            description="自定义工具",
            inputSchema={
                "type": "object",

    if name == "my_tool":
        result = process(arguments["input"])
        return [TextContent(type="text", text=result)]

if __name__ == "__main__":
    server.run(transport="stdio")

    概述

    Hermes Agent 内置了 Cron 定时任务系统，可以按时间调度执行 AI 任务。

    任务可以向不同渠道投递结果，支持纯脚本模式和 AI 增强模式。

    目录结构

    ~/.hermes/profiles/default/cron/
├── daily-report.yaml      # 每日报告任务
├── weekly-review.yaml     # 每周回顾任务
├── monitor.yaml           # 监控任务
└── ...

    每个 .yaml 文件定义一个独立的定时任务。

    任务文件格式

    # ~/.hermes/profiles/default/cron/daily-report.yaml

# 任务名称
name: daily-report

# Cron 表达式（标准格式）
schedule: "0 9 * * *"           # 每天早上 9 点

# 执行模式
mode: ai                        # ai | script

# AI 模式：prompt 发送给 Hermes Agent
prompt: |
  请生成今日工作报告：
  1. 检查今天的 git 提交记录
  2. 总结完成的任务
  3. 列出待处理事项
  输出格式为 Markdown

# 投递目标
delivery:
  type: chat                    # chat | email | webhook | file
  target: default               # 投递到默认聊天
  format: markdown              # 输出格式

# 任务元数据
description: "每天早上自动生成工作报告"
enabled: true
timeout: 300                    # 超时秒数

    Cron 表达式

    标准 5 字段格式：

    ┌───────── 分钟 (0-59)
│ ┌─────── 小时 (0-23)
│ │ ┌───── 日 (1-31)
│ │ │ ┌─── 月 (1-12)
│ │ │ │ ┌─ 星期 (0-6, 0=周日)
│ │ │ │ │
* * * * *

    常用示例：

    # 每 5 分钟
schedule: "*/5 * * * *"

# 每小时
schedule: "0 * * * *"

# 每天早上 8 点
schedule: "0 8 * * *"

# 每天下午 6 点
schedule: "0 18 * * *"

# 每周一早上 9 点
schedule: "0 9 * * 1"

# 每月 1 号
schedule: "0 0 1 * *"

# 工作日每天（周一到周五）
schedule: "0 9 * * 1-5"

# 每 30 分钟
schedule: "*/30 * * * *"

# 每天 8:30 和 18:30
schedule: "30 8,18 * * *"

    执行模式

    AI 模式（mode: ai）

    将 prompt 发送给 Hermes Agent，由 AI 执行并返回结果：

    mode: ai
prompt: |

    概述

    Hermes Agent 的记忆系统（Memories）允许 agent 跨会话持久化存储信息。

    记忆分为两个层级：user 级（用户全局偏好）和 memory 级（会话/主题记忆）。

    每条记忆是一段文本，存储在当前 profile 的 memories/ 目录下。

    记忆存储位置

    ~/.hermes/profiles/default/memories/
├── user.md              # 用户全局记忆（偏好设置）
├── preferences.md       # 用户偏好
├── project-context.md   # 项目上下文
├── notes.md             # 备忘录
└── ...

    每个 .md 文件是一组相关记忆的集合。

    memory 工具 API

    memory 是内置工具，用于管理记忆。核心参数：

    参数说明

    参数类型必需说明
    targetstring是user 或 memory
    keystring是记忆文件名（不含 .md 后缀）
    actionstring是add / replace / remove
    contentstring视情况要添加/替换的内容

    target 区别

  • user: 用户级别的全局记忆，通常存储偏好、身份信息、常用设置
  • memory: 通用记忆，按主题存储各种上下文信息

    • action 说明

  • add: 追加内容到记忆文件末尾
  • replace: 替换整个记忆文件的内容
  • remove: 删除指定的记忆文件

    常见陷阱

    陷阱 1：Skill 冲突

    问题：多个 skill 同时触发，行为混乱

    解决：

    # 使用更精确的 trigger
triggers:
  - regex: "^帮我审查.*Python.*代码$"  # 更精确
  # 而不是
  # - "代码"  # 太宽泛

    陷阱 2：MCP Server 启动慢

    问题：Agent 启动要等所有 MCP Server 就绪

    解决：

    mcp_servers:
  slow-server:
    command: python3
    args: ["/path/to/server.py"]
    timeout: 60           # 增加超时
    restart: true          # 崩溃自动重启

    陷阱 3：记忆污染

    问题：旧的记忆影响新的任务

    解决：

    # 定期审查记忆
cat ~/.hermes/profiles/default/memories/*.md

# 删除过时记忆
rm ~/.hermes/profiles/default/memories/old-project.md

# 或通过对话清理
# 用户：删除关于 xxx 项目的所有记忆

    陷阱 4：上下文窗口溢出

    问题：长对话导致上下文超出模型限制

    解决：

    # 减少历史长度
history_length: 15

# 或在对话中及时重置
# 用户：/clear

    陷阱 5：环境变量未加载

    问题：MCP Server 找不到 API Key

    解决：

    # 确保在 .bashrc / .zshrc 中设置
echo 'export BRAVE_API_KEY=xxx' >> ~/.bashrc
source ~/.bashrc

# 或在 config.yaml 中直接配置
# env:
#   BRAVE_API_KEY: "actual-key-here"

    陷阱 6：文件权限问题

    问题：Agent 无法读写某些文件

    解决：

    # 检查文件权限
ls -la ~/.hermes/profiles/default/

# 修复权限
chmod -R u+rw ~/.hermes/

# MCP Server 的 filesystem 限制了可访问目录
# 确保目标路径在配置的目录范围内

    陷阱 7：Profile 搞混

    问题：在错误的 profile 下创建了内容

    解决：

    # 确认当前 profile
echo $HERMES_PROFILE
hermes config get default_profile

# 移动文件到正确 profile
mv ~/.hermes/profiles/default/skills/wrong-skill \
   ~/.hermes/profiles/work/skills/
