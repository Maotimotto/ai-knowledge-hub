代码原理学习

学习之前你需要搞清楚git的工作原理：

通过跟踪文件的变化状态，在不同 "区域" 间流转和记录这些变化，最终实现对代码（或文件）的版本管理、协作开发等功能。理解 Git 的工作原理，关键在于掌握它的四大核心区域、文件状态流转和快照式存储机制。

一、四大核心区域

Git 中存在四个关键区域，文件在这些区域间流转，完成从修改到记录的全过程：

!Git 命令速查.png

  • 工作区（Working Directory）就是你本地看得见、正在编辑的文件目录。比如你在电脑上新建、修改的代码文件，都先存放在这里。工作区是 "临时" 的，所有修改还未被 Git 正式跟踪。
  • 暂存区（Staging Area / Index）位于工作区和本地仓库之间的 "过渡区域"，可以理解为一个 "待提交清单"。当你执行 git add <文件> 时，会将工作区中修改后的文件 "暂存" 到这里，标记为 "准备提交到仓库的内容"。暂存区的作用是：允许你分批选择要提交的修改（而不是一次性提交所有变化）。
  • 本地仓库（Local Repository）存储在本地的 Git 数据库（隐藏目录 .git 中），是 Git 的 "核心区域"。当你执行 git commit -m "说明" 时，暂存区的所有内容会被打包成一个 "版本快照"，永久记录到本地仓库中。每个快照都有唯一的哈希值（如 a1b2c3d），包含提交者、时间、提交信息以及指向快照内容的指针。
  • 远程仓库（Remote Repository）位于网络上的共享仓库（如 GitHub、GitLab 上的仓库），用于多人协作。本地仓库的修改可以通过 git push 推送到远程仓库，其他人可以通过 git pull 从远程仓库拉取最新版本到本地，实现代码同步。

    • 二、文件的状态流转

    在 Git 中，文件的状态会随着操作在上述区域间转换，主要有以下几种状态：

  • 未跟踪（Untracked）：新创建的文件，Git 还未记录过它的存在（只在工作区）。执行 git add 后变为 "已暂存"。
  • 已暂存（Staged）：文件修改已被添加到暂存区，等待提交到本地仓库。执行 git commit 后变为 "已提交"。
  • 已提交（Committed）：文件修改已被记录到本地仓库，成为一个历史版本。
  • 已修改（Modified）：已提交到仓库的文件被再次修改（仅在工作区），需要重新执行 git add 暂存，再 git commit 提交新的版本。

    • 简单来说，一个完整的 "修改 - 记录" 流程是：工作区修改 → git add → 暂存区 → git commit → 本地仓库 → git push → 远程仓库

    三、快照式存储：Git 的核心优势

    与其他版本控制系统（如 SVN）不同，Git 采用 "快照式存储" 而非 "差异比较"：

  • 每次 git commit 时，Git 不会只记录文件的修改部分，而是生成整个项目的 "快照"（即当前所有文件的完整状态）。
  • 为了高效存储，Git 会对未修改的文件复用之前的快照（通过指针指向），只保存修改过的文件的新副本，因此并不会占用过多空间。

    • 这种机制让 Git 的版本回退、分支切换等操作非常高效 —— 因为每个版本都是一个完整的快照，只需切换指针指向即可。

    四、分支：轻量化的版本线

    分支是 Git 最强大的功能之一，其本质是一个 "指向提交快照的指针"：

  • 新建分支（如 git branch feature）时，Git 只会创建一个新指针，指向当前的提交快照，几乎不占用额外空间。
  • HEAD 指针用于标记 "当前所在的分支"，切换分支（如 git checkout feature）本质是移动 HEAD 指针，指向目标分支的最新提交。
  • 不同分支可以独立开发（如主分支 main 保持稳定，功能分支 feature 开发新功能），完成后通过 git merge 将分支合并，实现协作开发。

    • 五、分布式：不依赖中央服务器

    Git 是分布式的，每个开发者的本地仓库都包含完整的历史记录（所有快照、分支信息），不依赖远程仓库也能完成提交、分支等操作。远程仓库的作用仅为 "同步和共享"，这使得：

  • 即使离线，也能正常提交代码、管理版本。
  • 单点故障（如远程仓库崩溃）不会导致历史记录丢失，因为每个本地仓库都是完整备份。

    • 总结来说，Git 的工作原理就是：通过四大区域管理文件状态，以快照方式记录每个版本，用轻量分支支持并行开发，最终通过分布式特性实现高效协作。理解这些核心概念，就能轻松掌握 Git 的各种操作逻辑。

    核心代码速查

    # 初始化一个新的 Git 仓库
git init

# 克隆远程仓库到本地
git clone <远程仓库URL>  # 例如: git clone https://github.com/example/repo.git

# 查看工作区和暂存区的状态
git status  # 显示已修改、已暂存、未跟踪的文件

# 将工作区的文件添加到暂存区
git add <文件名>  # 添加指定文件，例如: git add index.html
git add .        # 添加当前目录下所有修改和未跟踪的文件

# 将暂存区的文件提交到本地仓库
git commit -m "提交说明"  # -m 后面跟提交的描述信息

# 查看提交历史记录
git log               # 显示详细的提交历史
git log --oneline     # 简洁显示提交历史，每条记录一行
git log --graph       # 以图形化方式显示提交历史

# 查看远程仓库信息
git remote               # 显示远程仓库的简短名称
git remote -v            # 显示远程仓库的详细URL

# 添加远程仓库
git remote add <远程仓库名称> <远程仓库URL>  # 例如: git remote add origin https://github.com/example/repo.git

# 从远程仓库拉取最新代码
git pull <远程仓库名称> <分支名>  # 例如: git pull origin main，拉取并合并

# 将本地仓库的代码推送到远程仓库
git push <远程仓库名称> <分支名>  # 例如: git push origin main

# 创建新分支
git branch <分支名>  # 例如: git branch feature/login

# 切换到指定分支
git checkout <分支名>  # 例如: git checkout feature/login
git switch <分支名>    # 较新的命令，功能与checkout相同

# 创建并切换到新分支
git checkout -b <分支名>  # 例如: git checkout -b feature/payment
git switch -c <分支名>    # 较新的命令，功能同上

# 查看所有分支
git branch          # 列出本地分支，当前分支前有*标记
git branch -r       # 列出远程分支
git branch -a       # 列出所有分支（本地+远程）

# 合并分支到当前分支
git merge <要合并的分支名>  # 例如: 在main分支执行 git merge feature/login

# 删除本地分支
git branch -d <分支名>   # 安全删除，只有当分支已合并到主分支才会删除
git branch -D <分支名>   # 强制删除，无论是否合并

# 删除远程分支
git push <远程仓库名称> --delete <分支名>  # 例如: git push origin --delete feature/login

# 放弃工作区的修改
git checkout -- <文件名>  # 例如: git checkout -- index.html

# 取消暂存区的文件（将暂存区的修改放回工作区）
git reset HEAD <文件名>  # 例如: git reset HEAD index.html

# 回退到指定的提交版本
git reset --hard <提交ID>  # 例如: git reset --hard a1b2c3d，会丢弃之后的所有修改

# 查看文件的修改内容
git diff          # 查看工作区与暂存区的差异
git diff --cached # 查看暂存区与本地仓库的差异
git diff <分支1> <分支2>  # 查看两个分支之间的差异

# 暂存当前工作区的修改，以便切换到其他分支
git stash         # 暂存当前修改
git stash pop     # 恢复最近一次的暂存，并删除暂存记录
git stash list    # 查看所有暂存记录
git stash drop    # 删除最近一次的暂存记录

# 标签相关操作（通常用于标记发布版本）
git tag <标签名>              # 创建标签，例如: git tag v1.0.0
git tag                       # 查看所有标签
git push <远程仓库名称> <标签名>  # 推送标签到远程仓库，例如: git push origin v1.0.0

    入门

    🎯 全局定位：Git 版本控制的命令详解篇。从 git init 到分支管理，逐条讲解 Git 命令的用法和参数，适合需要深入理解每个命令的开发者。
    🔗 知识串联：← 上游：Git 学习笔记（原理）、命令速查 → 下游：IDE 集成操作 → 横向：Docker/Docker简介（Dockerfile 版本管理）
    ⚡ 难度标识：🟡 中等 — 从基础到进阶，逐步深入
    🛠️ 落地实践：AI 项目中的典型 Git 操作：git branch feature/rag-v2 创建 RAG 功能分支、git stash 暂存训练中的实验代码、git revert 回滚有问题的 Prompt 变更。

    使用Git前，需要先建立一个仓库(repository)。您可以使用一个已经存在的目录作为Git仓库或创建一个空目录。

    使用您当前目录作为Git仓库，我们只需使它初始化。

    git init

    使用我们指定目录作为Git仓库。

    git init newrepo

    从现在开始，我们将假设您在Git仓库根目录下，除非另有说明。

    添加新文件

    我们有一个仓库，但什么也没有，可以使用add命令添加文件。

    git add 'your_filename'

    可以使用add... 继续添加任务文件。

    可以使用tab补全

    也可以使用 . 添加所有

    git add .

    提交版本

    提交到本地仓库

    git commit -m "Adding files"

    如果您不使用-m，会出现编辑器来让你写自己的注释信息。

    当我们修改了很多文件，而不想每一个都add，想commit自动来提交本地修改，我们可以使用-a标识。

    git commit -a -m "Changed some files"

    git commit 命令的-a选项可将所有被修改或者已删除的且已经被git管理的文档提交到仓库中。

    千万注意，-a不会造成新文件被提交，只能修改。

    发布版本

    我们先从服务器克隆一个库并上传。

    git clone ssh://example.com/~/www/project.git

    现在我们修改之后可以进行推送到服务器。

    git push ssh://example.com/~/www/project.git

    取回更新

    如果您已经按上面的进行push，下面命令表示，当前分支自动与唯一一个追踪分支进行合并。

    git pull

    从非默认位置更新到指定的url。

    git pull http://git.example.com/project.git

    已经超过了五分钟？

    删除

    如何你想从资源库中删除文件，我们使用rm。

    git rm file

    分支与合并

    分支在本地完成，速度快。要创建一个新的分支，我们使用branch命令。

    git branch test

    branch命令不会将我们带入分支，只是创建一个新分支。所以我们使用checkout命令来更改分支。

    git checkout test

    第一个分支，或主分支，被称为"master"。

    git checkout master

    对其他分支的更改不会反映在主分支上。如果想将更改提交到主分支，则需切换回master分支，然后使用合并。

    git checkout master
git merge test

    如果您想删除分支，我们使用-d标识。

    git branch -d test
