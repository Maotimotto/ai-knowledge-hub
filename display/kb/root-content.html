    • 概述

    SmartRecruit 项目采用两级切分策略（Parent-Child Chunking）来处理简历文档：

  • 父块（Parent Chunk）：较大的文本块，用于保持上下文完整性
  • 子块（Child Chunk）：较小的文本块，用于精确检索

    • 这种策略的优势：

  • 检索时使用子块，提高检索精度
  • 返回时使用父块，保持上下文完整性
  • 支持不同文件类型的智能切分（Markdown vs 普通文本）

    1.1 文件哈希计算

    def compute_file_hash(file_path: str) -> str:
    hasher = hashlib.md5()
    try:
        with open(file_path, "rb") as f:
            for chunk in iter(lambda: f.read(4096), b""):
                hasher.update(chunk)
        return hasher.hexdigest()
    except Exception as e:
        logger.error(f"计算文件hash失败: {file_path}, 错误: {str(e)}")
        raise

    解析:

  • 使用 MD5 算法计算文件的唯一哈希值
  • 分块读取文件（每次 4096 字节），避免大文件占用过多内存
  • 哈希值用于：
  • 去重：避免重复存储相同文件
  • 关联：将切分后的子块与原始文档关联

    • 1.2 文档内容加载

    def load_and_hash_document(file_path: str, client: OpenAI) -> (str, str):
    logger.info(f"开始加载并哈希文件: {file_path}")
    file_extension = os.path.splitext(file_path)[1].lower()
    content = ""
    
    if file_extension not in document_loaders:
        raise ValueError(f"不支持的文件类型: {file_extension}")

    try:
        if file_extension in [".jpg", ".png"]:
            content = extract_text_from_image(file_path, client)
        else:
            loader_class = document_loaders[file_extension]
            if file_extension == ".txt":
                encodings = ["utf-8", "gbk", "latin1"]
                for enc in encodings:
                    try:
                        loader = loader_class(file_path, encoding=enc)
                        content = loader.load()[0].page_content
                        break
                    except UnicodeDecodeError:
                        continue
            else:
                loader = loader_class(file_path)
                content = loader.load()[0].page_content
        
        doc_hash = compute_file_hash(file_path)
        logger.info(f"文件加载并哈希成功: {file_path}, hash: {doc_hash}")
        return content, doc_hash
    except Exception as e:
        logger.error(f"加载或哈希文件失败: {file_path}, 错误: {str(e)}")
        raise

    解析:

  • 多格式支持：根据文件扩展名选择对应的加载器
  • .txt: TextLoader（支持多种编码尝试）
  • .pdf: PyPDFLoader
  • .docx: Docx2txtLoader
  • .md: UnstructuredMarkdownLoader
  • .jpg/.png: 使用 OCR 提取文本
  • 编码处理：对于 .txt 文件，依次尝试 UTF-8、GBK、Latin1 编码
  • 返回值：返回文档内容和文件哈希值

    存储流程

    def store_resume(self, doc: Document, chunks: List[Document], structured_data: Dict[str, Any]) -> bool:
    doc_hash = doc.metadata["hash"]
    
    # 检查是否已存在
    if self.mongo_collection.find_one({"doc_hash": doc_hash}):
        return False
    
    if not chunks:
        return False

    # 提取所有文档块的文本内容
    texts = [chunk.page_content for chunk in chunks]
    
    # 使用嵌入函数为文本生成嵌入向量
    embeddings = self.embedding_function.encode_documents(texts)

    # 构造插入数据
    data_to_insert = []
    for idx, chunk in enumerate(chunks):
        # 提取稀疏向量
        sparse_indices = embeddings["sparse"].indices[
                         embeddings["sparse"].indptr[idx]:embeddings["sparse"].indptr[idx + 1]]
        sparse_data = embeddings["sparse"].data[
                      embeddings["sparse"].indptr[idx]:embeddings["sparse"].indptr[idx + 1]]
        sparse_vector = {int(k): float(v) for k, v in zip(sparse_indices, sparse_data)}

        # 构造单个文档块的数据
        chunk_data = {
            "id": chunk.metadata["id"],
            "text": chunk.page_content,  # 子块内容
            "dense_vector": embeddings["dense"][idx].tolist(),
            "sparse_vector": sparse_vector,
            "doc_hash": doc_hash,
            **structured_data,
            "parent_content": chunk.metadata.get("parent_content", "")  # 父块内容
        }
        data_to_insert.append(chunk_data)

    # 插入到 Milvus
    self.client.insert(config.MILVUS_COLLECTION_NAME, data_to_insert)
    
    # 索引到 Elasticsearch
    for chunk in chunks:
        es_doc = {"content": chunk.page_content, "metadata": chunk.metadata}
        self.es_client.index(index=config.ES_INDEX_NAME, id=chunk.metadata["id"], document=es_doc)
    
    # 存储完整文档到 MongoDB
    mongo_doc = {"doc_hash": doc_hash, "content": doc.page_content, "metadata": doc.metadata,
                 "structured_data": structured_data}
    self.mongo_collection.insert_one(mongo_doc)
    
    return True

    解析:

  • 去重检查：通过 doc_hash 检查文档是否已存在
  • 向量生成：为每个子块生成稠密向量和稀疏向量（使用 BGE-M3 模型）
  • 存储到 Milvus：
  • 存储子块内容（text）
  • 存储父块内容（parent_content）
  • 存储结构化信息（姓名、性别、年龄、工作年限）
  • 索引到 Elasticsearch：用于关键词检索
  • 存储到 MongoDB：保存完整文档，用于最终返回

    Q1: 请介绍一下这个项目的背景，为什么选择做公告解读这个方向？

    A: 这个项目源于我在SmartRecruit项目中的启发。A股市场每年发布超过百万份上市公司公告，包含大量投资信息，但存在三个核心痛点：

  • 时间成本高：一份年报200-300页，专业投资者读透需要4-5小时
  • 信息过载：关键信息埋藏在冗长文本中，难以快速定位
  • 理解门槛高：会计术语、法律条款、监管要求对普通投资者不友好

    • 我选择这个方向是因为：

  • 市场空白：市面上没有专注公告解读的产品，大厂主要做全市场分析
  • 技术可行：RAG+LLM技术已经成熟，可以解决信息提取和理解问题
  • 商业价值明确：To-B客户（财经媒体、券商、私募）付费意愿强，ROI清晰

    A: 主要基于三个考虑：

  • 付费能力：财经媒体、券商客户经理、小型私募有明确预算，单个客户月付费可达5000-10000元
  • 使用场景明确：To-B客户有批量处理需求，API集成需求，更适合我们的技术架构
  • 获客成本低：通过行业会议、合作伙伴推荐，获客成本远低于To-C的广告投放

    • 二、技术选型类问题

    Q4: 为什么选择FastAPI而不是Flask或Django？

    A: 主要考虑三个因素：

  • 异步支持：FastAPI原生支持async/await，适合AI服务的异步调用场景（LLM API调用、向量检索都是IO密集型）
  • 性能优势：基于Starlette和Pydantic，性能接近Node.js，比Flask快2-3倍
  • 类型安全：Pydantic自动数据验证，减少运行时错误，提高开发效率

    • 在我们的场景中，需要同时处理PDF解析、向量检索、LLM调用等多个异步任务，FastAPI的异步特性显著提升了并发处理能力。

    Q5: 为什么选择Chroma而不是Milvus作为向量数据库？

    A: 这是一个权衡选择，主要考虑：

  • 轻量级部署：Chroma是Python原生，单机部署简单，无需Docker Compose等复杂配置
  • 开发效率：API简洁，集成LangChain生态方便，开发速度快
  • 成本控制：MVP阶段数据量不大（10万级公告），Chroma性能足够

    • 但我也知道Milvus的优势：在SmartRecruit项目中我使用过Milvus，它支持混合检索（稠密+稀疏向量）、分布式部署、更好的性能。如果项目扩展到百万级数据，我会考虑迁移到Milvus。

    Q6: PDF解析为什么选择PyMuPDF + PaddleOCR的组合？

    A: 这是基于实际测试的结果：

  • PyMuPDF（Fitz）：对于标准PDF（文本层存在），提取速度快、准确率高，是首选方案
  • PaddleOCR：对于扫描件PDF，PaddleOCR的中文识别准确率比Tesseract高15-20%，特别是对表格和复杂版面的处理
  • 降级策略：先尝试PyMuPDF，如果提取的文本长度<100字符，自动切换到PaddleOCR

    • 实际测试中，标准PDF占比约70%，扫描件约30%，这种组合方案在准确率和速度之间取得了平衡。

    Q7: 为什么选择BGE-M3而不是text2vec或m3e-base？

    A: BGE-M3有三个核心优势：

  • 多粒度检索：同时支持稠密向量和稀疏向量，稠密向量捕获语义，稀疏向量捕获关键词匹配，适合金融文本
  • 中文优化：在中文金融语料上微调，金融术语理解更好
  • 混合检索：可以同时进行语义检索和关键词检索，召回率提升30%

    • 在公告解读场景中，用户可能问"净利润增长"，也可能问"业绩预告"，BGE-M3的混合检索能力能同时召回相关结果。

    Q8: 为什么选择DeepSeek API而不是GPT-4或本地模型？

    A: 综合考虑了三个因素：

  • 成本：DeepSeek API价格是GPT-4的1/10，对于To-B产品，成本控制很重要
  • 中文能力：DeepSeek在中文金融文本理解上表现优秀，经过测试准确率与GPT-4相当
  • 响应速度：DeepSeek API延迟更低，平均响应时间1.5秒 vs GPT-4的3秒

    • 本地模型考虑：如果数据隐私要求高或成本敏感，我会考虑Qwen-7B等本地模型，但需要GPU资源，MVP阶段先采用API方案。

    Q32: BGE-M3的稠密向量和稀疏向量是如何融合的？

    A: BGE-M3采用了混合检索（Hybrid Search）机制：

    稠密向量（Dense Vector）：

  • 维度：1024维
  • 作用：捕获语义相似度
  • 例如："净利润增长"和"业绩提升"语义相似，稠密向量距离近

    • 稀疏向量（Sparse Vector）：

  • 维度：250000维（词汇表大小）
  • 作用：捕获关键词匹配
  • 例如："净利润"这个关键词在查询和文档中都出现，稀疏向量对应维度值高

    • 融合方式：

    # 伪代码
dense_score = cosine_similarity(query_dense, doc_dense)
sparse_score = dot_product(query_sparse, doc_sparse)
final_score = 0.7 * dense_score + 0.3 * sparse_score

    权重调优：

  • 通过A/B测试，发现0.7:0.3的权重效果最好
  • 金融文本中关键词匹配很重要，所以稀疏向量权重不能太低

    • Q33: 重排序模型（Reranker）是如何工作的？

    A: 我使用的是CrossEncoder重排模型：

    原理：

  • CrossEncoder将查询和文档拼接，输入BERT模型
  • 输出一个相关性分数（0-1之间）
  • 相比向量检索，CrossEncoder能看到查询-文档的完整交互

    • 实现：

    # 伪代码
pairs = [[query, doc1], [query, doc2], ...]
scores = reranker.predict(pairs)  # 批量预测
sorted_docs = sort_by_score(docs, scores)

    为什么需要重排：

  • 向量检索可能召回语义相关但实际不相关的文档
  • 例如：查询"业绩预告"，可能召回"业绩快报"（语义相似但不完全匹配）
  • 重排模型能更准确判断相关性

    • 性能优化：

  • 只对Top-20结果重排，避免全量重排（太慢）
  • 使用GPU加速，批量预测（batch_size=32）
  • 重排时间控制在100ms以内

  • 完整性：是否覆盖所有关键信息（人工评估，目标>85%）

  • 用户满意度：用户反馈"有用"的比例（目标>85%）
  • 任务完成率：用户成功获取所需信息的比例（目标>80%）

    • 4. 业务指标：

  • 解读准确率：与人工解读的一致性（目标>90%）
  • 用户留存率：用户持续使用的比例（目标>40%）

    class SSECollector:
        BASE_URL = "http://www.sse.com.cn"

        async def fetch_recent_announcements(self, hours=1):
            """获取最近N小时内的公告列表"""
            async with aiohttp.ClientSession(headers=self.HEADERS) as session:
                params = {
                    'beginTime': (datetime.now() - timedelta(hours=hours)).strftime('%Y-%m-%d %H:%M:%S'),
                    'endTime': datetime.now().strftime('%Y-%m-%d %H:%M:%S'),
                    'pageNo': 1,
                    'pageSize': 100
                }
                async with session.get(self.LIST_API, params=params, ssl=False) as resp:
                    data = await resp.json()
                    return self._parse_list(data['data'])

        def _parse_list(self, raw_list):
            """解析列表API返回的数据"""
            parsed = []
            for item in raw_list:
                # 构造唯一ID：股票代码_发布时间(yyyymmdd)_标题哈希前4位
                pub_time = datetime.strptime(item['publishTime'], '%Y-%m-%d %H:%M:%S')
                unique_id = f"{item['stockCode']}_{pub_time.strftime('%Y%m%d')}_{hashlib.md5(item['title'].encode()).hexdigest()[:4]}"
                parsed.append({
                    'announcement_id': unique_id,
                    'stock_code': item['stockCode'],
                    'title': item['title'],
                    'publish_time': pub_time,
                    'pdf_url': urljoin(self.BASE_URL, item['pdfUrl']),
                    'source': 'SSE'
                })
            return parsed

        async def download_pdf(self, item, save_dir='/data/announcements/raw_pdfs/'):
            """下载PDF文件"""
            local_path = f"{save_dir}{item['publish_time'].strftime('%Y-%m')}/{item['announcement_id']}.pdf"
            os.makedirs(os.path.dirname(local_path), exist_ok=True)
            async with aiohttp.ClientSession() as session:
                async with session.get(item['pdf_url']) as resp:
                    if resp.status == 200:
                        content = await resp.read()
                        with open(local_path, 'wb') as f:
                            f.write(content)
                        item['pdf_local_path'] = local_path
                        item['file_size'] = len(content)
                        return True
            return False

        async def run(self, interval_seconds=300):
            """主循环：定时抓取、去重、下载"""
            while True:
                try:
                    recent_items = await self.fetch_recent_announcements(hours=24) # 拉取24小时作为缓冲
                    for item in recent_items:
                        # 去重检查
                        exists = await self.db.check_announcement_exists(item['announcement_id'])
                        if not exists:
                            print(f"发现新公告: {item['announcement_id']}")
                            # 下载PDF

                            if success:
                                # 存入MySQL (状态为downloaded)

                            else:
                                print(f"下载失败: {item['announcement_id']}")
                except Exception as e:
                    print(f"采集循环出错: {e}")
                await asyncio.sleep(interval_seconds)

                    "text": text,
                    "blocks": self._split_into_blocks(text) # 按段落或标点分割

    # retrievers/hybrid_retriever.py
from rank_bm25 import BM25Okapi
from FlagEmbedding import FlagReranker
import numpy as np

class HybridRetriever:
    def __init__(self, milvus_collection, mongo_client, reranker_model_name='BAAI/bge-reranker-large'):
        self.milvus_collection = milvus_collection
        self.mongo_client = mongo_client
        self.reranker = FlagReranker(reranker_model_name, use_fp16=True)
        # 初始化BM25（需要提前加载所有文档的tokenized文本）
        self._init_bm25()

    def _init_bm25(self):
        """从MongoDB加载所有公告全文，初始化BM25索引（需定期更新）"""
        docs = self.mongo_client.announcement_docs.find({}, {"_id":1, "raw_text":1})
        self.doc_ids = []
        self.corpus = []
        for doc in docs:
            self.doc_ids.append(doc['_id'])
            self.corpus.append(self._tokenize(doc['raw_text']))
        if self.corpus:
            self.bm25 = BM25Okapi(self.corpus)

    def _tokenize(self, text):
        # 简单的分词，可使用jieba增强
        return text.split()

    def dense_search(self, query: str, top_k: int = 50):
        """Milvus向量检索"""
        from services.vector_service import VectorizationService
        vs = VectorizationService()
        query_vec = vs.create_embedding(query)
        search_params = {"metric_type": "COSINE", "params": {"nprobe": 10}}
        results = self.milvus_collection.search(
            data=[query_vec],
            anns_field="embedding",
            param=search_params,
            limit=top_k,
            output_fields=["announcement_id", "text", "metadata"]
        )
        return results

    def sparse_search(self, query: str, top_k: int = 50):
        """BM25全文检索"""
        tokenized_query = self._tokenize(query)
        scores = self.bm25.get_scores(tokenized_query)
        top_indices = np.argsort(scores)[::-1][:top_k]
        results = []
        for idx in top_indices:
            doc_id = self.doc_ids[idx]
            # 从MongoDB获取文档信息
            doc = self.mongo_client.announcement_docs.find_one({"_id": doc_id}, {"announcement_id":1, "raw_text":1})
            if doc:
                results.append({
                    "announcement_id": doc['announcement_id'],
                    "score": float(scores[idx]),
                    "text": doc['raw_text'][:500]  # 片段
                })
        return results

    def hybrid_rerank(self, query: str, dense_results, sparse_results, top_k: int = 10):
        """融合并重排"""
        # 1. 融合：将两种检索结果合并，去重
        all_candidates = {}
        for r in dense_results[0]: # 假设dense_results是Milvus返回格式
            aid = r.entity.get('announcement_id')
            all_candidates[aid] = {
                "announcement_id": aid,
                "dense_score": r.score,
                "text": r.entity.get('text'),
                "source": "dense"
            }
        for r in sparse_results:
            aid = r['announcement_id']
            if aid in all_candidates:
                all_candidates[aid]['sparse_score'] = r['score']
                all_candidates[aid]['source'] = 'hybrid'
            else:
                all_candidates[aid] = {
                    "announcement_id": aid,
                    "sparse_score": r['score'],
                    "text": r['text'],
                    "source": "sparse"
                }
        candidates = list(all_candidates.values())

        # 2. 粗排：加权融合分数 (可调整权重)
        for cand in candidates:
            dense_s = cand.get('dense_score', 0)
            sparse_s = cand.get('sparse_score', 0)
            cand['coarse_score'] = 0.7 * dense_s + 0.3 * sparse_s

        # 3. 精排：使用Reranker模型对Top N粗排结果重新打分
        candidates_sorted = sorted(candidates, key=lambda x: x['coarse_score'], reverse=True)[:20]
        pairs = [(query, cand['text']) for cand in candidates_sorted]
        rerank_scores = self.reranker.compute_score(pairs)  # 返回分数列表

        for i, score in enumerate(rerank_scores):
            candidates_sorted[i]['rerank_score'] = score

        # 4. 按精排分数返回最终Top-K
        final_results = sorted(candidates_sorted, key=lambda x: x.get('rerank_score', 0), reverse=True)[:top_k]
        return final_results

    # engines/qa_engine.py
import openai
from tenacity import retry, stop_after_attempt, wait_exponential
import redis
import json

class QAEngine:
    def __init__(self, llm_config, retriever: HybridRetriever, redis_client: redis.Redis):
        openai.api_key = llm_config['api_key']
        openai.api_base = llm_config.get('base_url', 'https://api.deepseek.com/v1')
        self.model = llm_config.get('model', 'deepseek-chat')
        self.retriever = retriever
        self.redis = redis_client

    @retry(stop=stop_after_attempt(2), wait=wait_exponential(multiplier=1, min=2, max=10))
    def ask(self, question: str, session_id: str = None, top_k: int = 5) -> dict:
        # 1. 混合检索
        dense_res = self.retriever.dense_search(question, top_k=top_k*2)
        sparse_res = self.retriever.sparse_search(question, top_k=top_k*2)
        contexts = self.retriever.hybrid_rerank(question, dense_res, sparse_res, top_k=top_k)

        # 2. 准备Prompt上下文
        context_str = ""
        source_docs = []  # 用于缓存
        for i, ctx in enumerate(contexts):
            context_str += f"[来源{i+1}]: {ctx['text']}\n\n"
            source_docs.append({
                "announcement_id": ctx['announcement_id'],
                "text": ctx['text'],
                "score": ctx.get('rerank_score', 0)
            })

        prompt = f"""你是一位专业的上市公司公告分析助手。请基于以下公告信息，准确、简洁地回答用户问题。
        如果信息不足，请明确说明。

        【相关公告信息】
        {context_str}

        【用户问题】
        {question}

        请按以下格式回答：
        1. 核心答案（直接、简洁）。
        2. 详细依据（引用相关来源，如[来源1]）。
        3. 风险提示（如果相关）。
        """
        # 3. 调用LLM
        try:
            response = openai.ChatCompletion.create(
                model=self.model,
                messages=[
                    {"role": "system", "content": "你只根据提供的公告信息回答问题，不虚构信息。"},
                    {"role": "user", "content": prompt}
                ],
                temperature=0.1,
                max_tokens=800,
                stream=False
            )
            answer = response.choices[0].message.content

            # 4. 异步缓存检索到的原文 (使用Celery任务)
            self._async_cache_source_docs(source_docs, session_id)

            # 5. 更新对话历史 (MongoDB)
            if session_id:
                self._update_conversation_history(session_id, question, answer, source_docs)

            return {
                "answer": answer,
                "sources": source_docs,
                "contexts": contexts
            }
        except Exception as e:
            return {"error": f"LLM生成失败: {e}"}

    def _async_cache_source_docs(self, source_docs, session_id):
        """将检索到的Top-K文档原文缓存到Redis，方便快速点击查看"""
        from tasks import cache_docs_task
        cache_docs_task.delay(source_docs, session_id)

    def _update_conversation_history(self, session_id, question, answer, source_docs):
        """更新MongoDB中的对话历史，管理10轮原文和20轮摘要"""
        from db.mongo_client import mongo_db
        collection = mongo_db.conversation_history
        # 获取或创建会话
        session = collection.find_one({"session_id": session_id})
        if not session:
            session = {"session_id": session_id, "messages": [], "raw_context_buffer": []}
        # 添加新消息摘要
        new_message = {"role": "user", "content": question, "timestamp": datetime.now()}
        session["messages"].append(new_message)
        new_message = {"role": "assistant", "content": answer, "timestamp": datetime.now(), "references": [doc['announcement_id'] for doc in source_docs]}
        session["messages"].append(new_message)
        # 保持最近20轮消息
        if len(session["messages"]) > 40:  # 20轮对话 (每轮user+assistant)
            session["messages"] = session["messages"][-40:]

        # 更新原始文本缓冲区 (最近10轮引用的原文)
        for doc in source_docs:
            raw_chunk = {
                "doc_id": doc['announcement_id'],
                "chunk_id": f"{doc['announcement_id']}_chunk_0",
                "text": doc['text'][:1000]  # 存前1000字符
            }
            session["raw_context_buffer"].append(raw_chunk)
        # 保持最近10轮引用的原文
        if len(session["raw_context_buffer"]) > 10:
            session["raw_context_buffer"] = session["raw_context_buffer"][-10:]

        collection.update_one({"session_id": session_id}, {"$set": session}, upsert=True)
