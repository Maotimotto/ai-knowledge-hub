数据类型与预处理

⭐ 初级

RAG 系统需要处理三种数据类型，它们在存储方式和处理方法上截然不同。
  • 结构化数据：SQL 表、CSV、Excel → 存入关系型数据库（RDBMS），用 SQL 查询
  • 半结构化数据：JSON、XML、HTML → 存入 NoSQL（MongoDB），灵活可嵌套
  • 非结构化数据：文本、PDF、图片、音视频 → 存入向量数据库（Milvus/Chroma），需 Embedding 转换
💡 关键认知

非结构化数据约占 80%，LLM 通过 Embedding 将其转化为可计算的向量，解锁了海量沉睡数据的价值。

多模态文档解析 — Docling

在企业级 RAG 中，80% 的价值信息在 PDF 的表格和图片中。传统纯文本提取会导致语义断层。

表格处理策略

策略说明
行级原子化每行转为 [表格标题] + [表头] + [当前行数据]，检索精度最高
HTML 序列化比 Markdown 更保留层级结构（rowspan/colspan），GPT-4o 推理更强
强制携带表头长表拆分时，每块必须带表头，防止数据丢失索引

图片处理流程

  1. Docling 导出图片 Base64
  2. 结合图片周边文字（图注）作为 Prompt 上下文
  3. VLM（如 GPT-4o-mini）生成文字描述
  4. 将描述 + 原图路径存入向量库（实现"以文搜图"）

🔧 工程要点
  • 表格解析首选 Docling（IBM 开源，内置 TableFormer 模型）
  • 图片不直接检索像素，而是检索其"语义代理"（Caption）
  • 永远不要孤立存储表格，必须带上上下文标题

切片策略总览

⭐⭐ 中级

分块（Chunking）是 RAG 从"玩具"走向"工业级"的分水岭。检索不准 80% 不是模型问题，而是文档"切碎了"或"切错了"。

四种切片策略对比

策略复杂度优点缺点适用场景
递归字符分块低通用、保留语义边界仍有概率切断逻辑通用场景首选
滑动窗口分块低减少断裂风险冗余多，费 Token短文档
向量语义分块中逻辑最连贯，检索最准多一次 Embedding 推理高质量知识库
模型语义分块高捕捉长程依赖推理成本高法律合同、财报

1. 递归字符分块

（Recursive Character Splitting）— 最重要的通用方案，LangChain 默认推荐。

核心逻辑：不是按长度一刀切，而是"带着备选方案的尝试切分"。

分隔符优先级：\n\n（段落）→ \n（行）→ （词）→ ""（字符）

关键参数：

  • chunk_size：通常 512-1024 token
  • chunk_overlap：50-100 字符，给断开的语义贴"创可贴"
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=512,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", " ", ""]
)
chunks = splitter.split_text(text)

2. 向量语义分块

（Semantic Chunking）— 不按字数切，而是计算相邻句子的向量相似度，在语义"断层"处切分。

from FlagEmbedding import FlagModel
import numpy as np

model = FlagModel('BAAI/bge-small-zh-v1.5')

def semantic_chunking(text, threshold=0.85):
    sentences = text.split('。')
    embeddings = model.encode(sentences)
    chunks, current = [], [sentences[0]]
    for i in range(len(sentences) - 1):
        sim = np.dot(embeddings[i], embeddings[i+1]) / (
            np.linalg.norm(embeddings[i]) * np.linalg.norm(embeddings[i+1]))
        if sim > threshold:
            current.append(sentences[i+1])
        else:
            chunks.append("。".join(current))
            current = [sentences[i+1]]
    chunks.append("。".join(current))
    return chunks

3. 模型语义分块

（Model-based / Agentic Chunking）— 利用 LLM 或 Reranker 判断逻辑边界。

优化策略："先暴力，再精修"——先用 BGE 向量距离初步切分，模糊地带再调用轻量级模型二审。

from FlagEmbedding import FlagReranker

reranker = FlagReranker('BAAI/bge-reranker-v2-m3', use_fp16=True)

def model_based_split(text_list):
    chunks, current = [], text_list[0]
    for i in range(1, len(text_list)):
        score = reranker.compute_score([current, text_list[i]])
        if score > 0.0:
            current += " " + text_list[i]
        else:
            chunks.append(current)
            current = text_list[i]
    chunks.append(current)
    return chunks

4. 父子文档构建

（Parent-Child Retrieval）

核心思想："搜索用小块，生成用大块"

  • 子文档（Child）：100-200 token，保证检索敏感度
  • 父文档（Parent）：500-2000 token，保证语境完整
from langchain.retrievers import ParentDocumentRetriever
from langchain_text_splitters import RecursiveCharacterTextSplitter

parent_splitter = RecursiveCharacterTextSplitter(chunk_size=500)
child_splitter = RecursiveCharacterTextSplitter(chunk_size=50)

retriever = ParentDocumentRetriever(
    vectorstore=vectorstore,
    docstore=store,
    child_splitter=child_splitter,
    parent_splitter=parent_splitter,
)

6. 文档块摘要索引

（Chunk Summary Index）— 先让 LLM 把每个块总结成摘要，用摘要向量索引。

原则：检索用摘要，回答用原文。

工程要点

🔧 关键经验
  • 一个完整逻辑的 1000 字 Chunk > 三个逻辑断裂的 300 字 Chunk
  • 语义分块是离线过程，不影响在线搜索延迟
  • 可用轻量模型分块，检索时换回大模型
