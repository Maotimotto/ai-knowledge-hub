RAG 四大评估指标

⭐⭐⭐ 高级

"没有评估，就没有优化。"RAG 评估基于 RAGAS 框架的四个核心指标，分别测量检索和生成两个环节的质量。

检索质量

指标问题衡量对象
Context Recall找全了吗？检索片段是否覆盖答案所需的全部知识点
Context Precision找准了吗？有用信息是否排在前面，噪音多不多

生成质量

指标问题衡量对象
Faithfulness瞎编了吗？答案是否完全来自检索片段（反幻觉）
Answer Relevance答非所问吗？答案是否直击用户问题核心

对症下药

指标低优化方向
Context Recall 低优化 Embedding 和分块策略
Context Precision 低加 Reranker 重排
Faithfulness 低调低 Temperature，加 Prompt 约束
Answer Relevance 低优化 Prompt 模板

自动化评估（RAGAS）

from ragas import evaluate
from ragas.metrics import context_recall, context_precision, faithfulness, answer_relevance
from datasets import Dataset

data_sample = {
    "question": ["BGE-M3的最大长度是多少？"],
    "answer": ["BGE-M3支持8192个token。"],
    "contexts": [["BGE-M3支持最高8192 token。"]],
    "ground_truth": ["BGE-M3支持8192个token。"]
}
dataset = Dataset.from_dict(data_sample)
score = evaluate(dataset, metrics=[context_recall, context_precision, faithfulness, answer_relevance])

无标准答案时：用 LLM-as-a-Judge（如 GPT-4o）充当裁判打分。

Self-RAG

传统 RAG 是死板流水线，Self-RAG 通过植入反思令牌实现闭环反馈：

  1. [Retrieve]：按需检索，知识储备不足时才翻书
  2. [IsRel]：相关性过滤，不相关的直接踢掉
  3. [IsSup]：忠实度检查，每句话对比原文
用户提问 → 意图识别 → {需要检索?} → Yes → 多路检索+Rerank
                                 → No → 模型原生知识
         → [IsRel] 过滤 → 生成答案 → [IsSup] 自检
         → 忠实度低 → 自我修正 → 忠实度高 → 输出
⚠️ 注意

真正的 Self-RAG 靠微调，Prompt 里写"请反思"只是伪 Self-RAG。

迭代检索增强生成（Iterative RAG）

对于复杂多跳问题，进行多次"检索→生成→再检索"循环：

def iterative_rag(question, max_rounds=3):
    context, current_query = "", question
    for i in range(max_rounds):
        info = retrieve(current_query)
        context += f"[证据{i+1}]: {info}"
        if is_sufficient(info, question):
            break
        current_query = generate_next_query(info, question)
    return llm.generate(question, context)

控制迭代深度：通常 2-3 次足够，过多会增加延迟和成本。

RAG 完整架构图

⭐⭐⭐ 高级

完整的 RAG 系统包含三个阶段：离线建库、在线检索融合、上下文组装生成。

RAG 三阶段架构全景

一、离线阶段（Indexing / 建库）

原始文档（法规/技术文档/PDF/Word）
        ↓
  文档解析 & 结构化
        ↓
┌─────────────────────────────┐
│      父块 Parent Chunk       │
│    （800-1500字，语义完整）    │
└─────────────────────────────┘
        ↓
  ┌─────┴──────┐
  ↓            ↓
子块          Summary
(150-300字)   (50-150字)
  ↓            ↓
jieba分词    Summary Embedding
  ↓            ↓
┌────────┐  ┌──────────────┐
│BM25索引│  │Summary向量库  │
└────────┘  └──────────────┘
  ↓
┌────────┐
│Dense向量│
│  库     │
└────────┘

二、在线阶段（Retrieval + Fusion + Rerank）

用户问题 Query
    ↓
（可选）多问题生成 / Query Rewrite
    ↓
─── 并行检索（三条通道）───

1️⃣ Dense 检索（子块）
   Query → Embedding → 子块 Vector DB → TopK 子块

2️⃣ BM25 检索（子块）
   Query → 分词 → BM25 倒排索引 → TopK 子块

3️⃣ Dense 检索（Summary）
   Query → Embedding → Summary Vector DB → TopK parent_id

    ↓
候选合并（子块层）
    ↓
RRF 融合排序（子块级）
    ↓
Rerank 精排（Cross-Encoder）
    ↓
TopN 子块（8-15个）
    ↓
按 parent_id 去重
    ↓
召回父块 Parent Chunk（3-6个）

三、上下文组装 & 回答阶段

父块 Contexts
├─ 原文内容
├─ 命中子块证据定位
├─ 条号/页码/来源
    ↓
Prompt 构建（问题 + 约束 + 上下文 + 证据）
    ↓
LLM 生成答案
    ↓
（可选）后处理：合规检查、证据引用、风险提示
🎯 三句话总控原则

Summary 定方向，子块定命中，父块定结论。

1. 知识库构建

qaQuestion + Answer 拼接中精度匹配，阈值 0.68
docs文档分块补充检索，阈值 0.3

2. 检索策略（分级路由）

def answer_by_vectorstore(query, history):
    # Level 1：高精度 Query 匹配
    high_docs = query_retriever.get_relevant_documents(query, filter={"type": "query"})
    if high_docs:
        return high_docs[0].metadata["answer"]  # 直接返回，不走 LLM
    
    # Level 2：中精度 QA 匹配 + BM25 补充
    qa_docs = qa_retriever.get_relevant_documents(query, filter={"type": "qa"})
    bm25_docs = bm25_retriever.get_relevant_documents(query)
    
    # Level 3：文档检索兜底
    if not qa_docs:
        doc_docs = doc_retriever.get_relevant_documents(query, filter={"type": "docs"})
    
    # 组装上下文 + LLM 生成
    background = combine_docs(qa_docs, bm25_docs, doc_docs)
    return llm.generate(background, history, query)

前缀树核心逻辑

# 构建：逐字符建节点
def add(node, keyword, weight=0):
    for i, char in enumerate(keyword):
        if char not in current:
            new_node = Node(char, is_leaf=(i == len(keyword)-1), weight=weight)
            current.add_subnode(new_node)
        current = current.get_subnode(char)

# 搜索：深度优先遍历 + 按权重排序
def search(node, prefix, limit=8):
    top_node = node.get_top_node(prefix)
    results = [(prefix + k, n) for k, n in depth_walk(top_node)]
    results.sort(key=lambda x: x[1].weight, reverse=True)
    return results[:limit]

面试高频问答

Q: 为什么不用 GraphRAG？

A: 知识是文档型和 QA 型，客服场景需要的是材料内内容问答，不需要高层级信息总结。GraphRAG 构建成本高、知识难更新。

Q: 如何做百万级数据的向量化？

A: 推荐购置云端向量数据库（如 Milvus Cloud），多节点高 CPU/内存共同负载。

Q: 混合检索为什么有效？

A: 稀疏检索精确匹配关键词/术语，稠密检索理解语义解决同义词问题，两者互补。

Q: Rerank 如何实现？

A: 使用 BGE-Reranker 对召回文本做基于 Cross-Encoder 的相似度排序，或加权计算重要性得分。
