概述与定位

RAG Pipeline 全流程

核心思路：LLM + 外部知识库检索 → 减少幻觉，提升准确性

RAG（检索增强生成）是 AI 应用栈中连接 LLM 与外部知识的核心桥梁。在 AI 大模型技术体系中，RAG 处于 LLM 基础能力之上的应用层，解决了 LLM 知识时效性、领域专业性和幻觉三大痛点。本文档是 RAG 技术知识体系的总入口，按「离线建库→查询处理→检索→后处理→生成评估→实战」六阶段组织。

大模型的局限性

LLM 虽然强大，但也存在一些很难根除的"疾病"：

1. 知识时效性

LLM 因其具有海量参数，需要花费相当的物力与时间成本进行预训练和微调，同时商用 LLM 还需要进行各种安全测试与风险评估等。因此 LLM 会存在一定的知识滞后问题，无法回答训练时间点之后相关的问题。

2. 领域知识缺失

LLM 掌握了大量通用知识。但是在一些细分小众专业领域，可能存在很少或者完全没有训练数据。因此 LLM 无法掌握或完全不了解该领域相关的知识。

3. 无法确定信息来源

LLM 在生成回答时，无法确定其回答内容的依据，也就无法确定其回答的可靠性。

4. 幻觉

LLM 在生成回答时，可能会一本正经的胡说八道，这被称为 LLM 的"幻觉"问题。产生的原因可能是训练知识存在偏差、过度泛化、缺乏深层理解或缺乏某些领域知识。

RAG 简介

为了改善 LLM 在时效性、可靠性与准确性方面的不足，各种针对 LLM 优化的方法应运而生。RAG（Retrieval-Augmented Generation，检索增强生成）就是其中一种被广泛研究和应用的优化架构。

RAG 的基本思想：将传统的生成式 LLM 和实时信息检索技术相结合，为 LLM 补充来自外部的相关数据和上下文，帮助 LLM 生成更加准确可靠的内容。RAG 就相当于在 LLM 回答时给它一本参考书。

数据索引阶段（Indexing）

  • 加载（Loading）：对各种格式的数据统一进行处理和解析
  • 分割（Splitting）：将较大的内容分割成一个个小的知识块
  • 嵌入（Embedding）：将知识块转换为向量
  • 索引（Indexing）：将向量化后的知识块存储到向量数据库中

数据查询阶段（Query）

  • 检索（Retrieval）：借助数据索引从存储库中查找出相关的知识块
  • 生成（Generation）：将相关知识块与用户查询构造为 Prompt，输入给 LLM

扩展阶段

  • 检索前处理（Pre-Retrieval）：查询转换、查询扩充、检索路由
  • 检索后处理（Post-Retrieval）：重排序、过滤、上下文压缩

RAG 与微调

比较内容RAG微调

训练成本无需额外训练成本需要数据准备、标注、清洗及算力成本
可解释性可追溯到具体数据来源可解释性较差

在实际场景中需要根据侧重点选择，条件允许时也可将 RAG 和微调结合使用。

RAG 架构演进

RAG 最早在 2020 年由 Meta 的技术团队在 Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks 中正式提出，2022 年 ChatGPT 出现后获得广泛关注。

Naive RAG（朴素RAG）

朴素 RAG 范式遵循传统基础流程：索引 → 检索 → 生成。

面临的问题

检索召回精度

  • 精确度（Precision）= 检索到的相关文档数 / 检索到的总文档数
  • 召回率（Recall）= 检索到的相关文档数 / 知识库中所有相关文档总数

大模型自身能力

LLM 是否能推理、识别并区分无关或矛盾数据，能否准确生成答案，能否避免敏感信息。

数据增强的障碍

如何将检索到的信息整合生成连贯、不重复、风格一致的答案。

上下文大小限制

知识块过多会导致留给生成的 token 过少；过少则遗漏关键信息。

响应性能

RAG 增加了更多处理步骤，端到端响应性能下降。

Advanced RAG（高级RAG）

高级 RAG 引入检索前处理和检索后处理两大部分来提高检索质量。

检索前处理

优化分块策略

较大的块捕获更多上下文但噪声更多；较小的块可能截断关键信息。后续提出 Small2Big 方法：句子用作检索单位，前后句子作为上下文。

元数据索引

使用元数据（页码、文件名、作者、时间戳）丰富数据块，实现时间感知检索。还可以构建假设性问题（逆向 HyDE）。

结构化索引

建立文档层次结构加快检索速度。

查询扩展

将单个查询扩展为多个查询，提供更完整的上下文。

查询重写

使用 LLM 或专门训练的小语言模型对查询内容进行重写。

HyDE

Hypothetical Document Embeddings：先生成假设答案文档，用假设文档进行向量化检索。

查询路由

根据用户查询特征，将其路由到不同的知识源、检索策略或子模型。

混合检索

结合稀疏检索（关键词匹配）和稠密检索（向量相似度）捕捉不同的相关特征。

检索后处理

重排序

将初步检索结果进行重新排序，突出最相关的信息。

上下文压缩

对检索到的文档或片段进行处理，在不丢失重要信息的前提下压缩长度和数量。

Graph RAG

Graph RAG 是一种结构化、分层的 RAG 方法。从原始文本中提取知识图谱，构建社区层次结构，为社区生成摘要，然后利用这些结构执行 RAG 任务。

Graph RAG 工作流程：

  1. LLM 处理数据集，创建对所有实体和关系的引用，构建知识图谱
  2. 对图谱自底向上聚类，将数据分层组织成语义簇（社区）
  3. 查询时，实体和社区都会用于为 LLM 提供上下文材料

Agentic RAG

Agentic RAG 通过引入能够进行动态决策和工作流优化的智能体，处理复杂、实时和多领域的查询。

主要特点

  • 自主决策：智能体根据查询复杂性独立评估和管理检索策略
  • 迭代优化：引入反馈循环提高检索准确性和响应相关性
  • 工作流优化：动态协调任务，实现实时应用

Agent 组成

  • LLM：主要推理引擎
  • 记忆：短期记忆（对话状态）+ 长期记忆（积累知识）
  • 规划：通过反思、查询路由或自我批评指导推理
  • 工具：扩展文本生成之外的能力

RAG 效果评估

质量分数评估

指标评估问题衡量对象
上下文相关性相关吗？检索到的上下文与查询之间的相关性
答案真实性有依据吗？生成的答案是否能被检索内容所支撑
答案相关性答对了吗？生成的答案与查询之间的相关性

基本能力评估

  • 抗噪声能力：处理缺乏实质性信息的噪声文档的能力
  • 负向拒绝：检索内容不足时拒绝回答的能力
  • 信息整合：从多个文档中综合信息的能力
  • 反事实鲁棒性：识别并忽略文档中已知错误的能力

评估工具 Ragas

Ragas 是开源的 RAG 端到端评估框架，包含多种评估指标：

  • 检索阶段：Context Precision、Context Recall、Context Entities Recall、Context Relevancy
  • 生成阶段：Response Groundedness、Faithfulness、Response Relevancy、Noise Sensitivity、Answer Accuracy

搭建 RAG 系统

核心模块

  • 索引：文档加载 → 文本分块 → 向量嵌入 → 向量存储
  • 检索：查询嵌入 → 相似度检索 → 提取上下文
  • 生成：提示工程 → LLM 调度 → 输出后处理
  • 服务接口：REST API → 流式响应 → 监控指标
