一、查询处理（Query Processing）

⭐⭐ 中级

RAG 中 80% 的检索失败不是向量库不行，而是用户"不会提问"。查询处理是连接用户模糊意图与知识库精确匹配的桥梁。

1. 查询重写（Query Rewriting）

将用户模糊的、不完整的提问转化为更适合检索系统的精确表达。

核心场景：

  • 多轮对话消解：用户说"他老婆呢？" → 重写为"周杰伦的老婆是谁？"
  • 口语化转换：用户搜"拉肚子" → 重写为"急性肠胃炎"
  • 错别字修正
def query_rewriter(history, current_query):
    prompt = f"""根据对话历史，将最新提问重写为完整的独立搜索关键词。
    要求：不要回答问题；包含代词请结合历史补充完整。
    对话历史：{history}
    最新提问：{current_query}
    重写后的提问："""
    return llm.invoke(prompt)

2. HyDE（假设性文档嵌入）

不直接拿问题去搜，而是先让 LLM 编造一个"假答案"，用假答案的向量去匹配真答案。

核心逻辑：由 "问题→答案" 检索，转变为 "答案→答案" 检索。

维度传统检索HyDE
语义对齐疑问句 vs 陈述句，特征偏移陈述句 vs 陈述句，高度重合
信息量问题短，特征稀疏假文档丰富，特征稠密
风险低LLM 理解错则检索南辕北辙

防幻觉措施：混合检索（HyDE + 原始 Query），字数限制 200-300 token。

3. Query2Doc（查询扩展）

给原问题 + 一段 LLM 生成的"伪答案"，拼接后去搜。

原始：iPhone 15 为什么断连？
扩展：iPhone 15 为什么断连？ 基带芯片、5G信号频率、移动通信天线

vs HyDE：Query2Doc 保留原问题（更稳健），HyDE 替换原问题（更激进）。企业级通常选 Query2Doc。

4. 多查询检索（Multi-Query）

将一个问题改写为 3-5 个语义相近的子问题，分别检索后用 RRF 融合。

def generate_queries(original):
    prompt = "请将以下问题改写为3个语义相关的短句"
    return llm.invoke(prompt.format(q=original))

# 并发检索 + RRF 融合
all_results = [search(q) for q in sub_queries]
final = rrf_fusion(all_results)

5. 查询扩展去幻觉

防止 LLM 扩展内容将检索带偏的四大绝招：

  1. 结构化 Prompt：要求只输出关键词，禁止解释性句子
  2. Few-shot 引导：给 LLM 好/坏扩展的示例
  3. 拒绝触发：不懂就闭嘴，重复原始问题
  4. 权重锚定：Vector_final = α·Vector_original + (1-α)·Vector_pseudo，α 通常 0.7+

策略选择指南

场景推荐策略
QPS 极高的电商搜索查询重写（轻量级）
专业领域（医疗/法律）HyDE + 混合检索
长尾难题/首轮失败Query2Doc
模糊语义搜索Multi-Query + RRF
多轮对话查询重写（上下文补全）

二、检索策略（Retrieval）

稠密检索（Dense Retrieval）

使用 Embedding 模型（如 BGE-M3）将文本转为稠密向量，通过余弦相似度/内积进行匹配。

BGE-M3 特点

  • 三路召回：稠密向量 + 稀疏向量 + 多向量
  • 支持最长 8192 token
  • 多语言支持（中英日韩等）

检索模式（以 Chroma/LangChain 为例）

# TopK 检索
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})

# 相似度阈值检索
retriever = vectorstore.as_retriever(
    search_type="similarity_score_threshold",
    search_kwargs={"score_threshold": 0.7}
)

# MMR 检索（多样性）
retriever = vectorstore.as_retriever(search_type="mmr")

稀疏检索（Sparse Retrieval）

基于 BM25 统计算法，通过关键词匹配进行检索。

BM25 核心原理

  • IDF：词在越少文档中出现，权重越高
  • TF + 长度归一化：词频越高权重越高，但对长文档惩罚
from langchain_community.retrievers import BM25Retriever
import jieba

def chinese_tokenizer(text):
    return jieba.lcut(text)

bm25_retriever = BM25Retriever.from_texts(
    doc_list,
    preprocess_func=chinese_tokenizer,
)
bm25_retriever.k = 5

混合检索（Hybrid Search）

结合稠密 + 稀疏检索，实现 1+1>2 效果。

检索方式优势劣势
稠密检索理解语义，解决词汇不匹配对数字/代号不敏感
稀疏检索精确匹配关键词/术语遭遇同义词无能为力
 
from langchain.retrievers import EnsembleRetriever

ensemble_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, dense_retriever],
    weights=[0.5, 0.5]
)

倒排索引（Elasticsearch）

通过词条找到包含它的所有文档 ID 列表，类似书末索引。

前缀树快速匹配

用于输入联想/自动补全场景（如证券交易所名称匹配）：

class Node(dict):
    def __init__(self, key, is_leaf=False, weight=0):
        self.key = key
        self.is_leaf = is_leaf
        self.weight = weight

def search(node, prefix, limit=8):
    top_node = node.get_top_node(prefix)
    results = [(prefix + subkey, pnode) 
               for subkey, pnode in depth_walk(top_node)]
    results.sort(key=lambda x: x[1].weight, reverse=True)
    return results[:limit]

三、检索后处理（Post-Retrieval）

向量检索是"海选"，检索后处理是"决赛圈精挑细选"。两个核心技术：Rerank（重排序）和 RRF（互惠排名融合）。

Rerank（重排序）

让昂贵的 Cross-Encoder 深度模型对初筛结果进行精排。

为什么需要 Rerank

  • 向量检索擅长模糊匹配，但对精确数字、否定词经常翻车
  • Bi-Encoder（Embedding 模型）速度快但精度有限
  • Cross-Encoder 精度高但计算量 O(N)，只能用于精排

典型流程

向量检索 Top-50 → Rerank 精排 → Top-5 送给 LLM

BGE-Reranker 使用

from FlagEmbedding import FlagReranker

reranker = FlagReranker('BAAI/bge-reranker-v2-m3', use_fp16=True)
score = reranker.compute_score([query, passage])

RRF（互惠排名融合）

一种不看"得分高低"，只看"排名先后"的公平投票机制。

核心公式

score(d) = Σ 1 / (k + r(d))

  • r(d)：文档在排行榜里的排名
  • k：平滑因子（通常 60），防止第一名权重过大

为什么不用加权评分

方案特点
加权评分Score = 0.3×Vector + 0.7×Keyword，需要手动调参，数据一变权重失效
RRF无需调参，只需排名，鲁棒性极强

实现代码

def rrf_fusion(rank_lists, k=60):
    rrf_score = {}
    for rank_list in rank_lists:
        for rank, doc_id in enumerate(rank_list):
            score = 1.0 / (k + rank + 1)
            rrf_score[doc_id] = rrf_score.get(doc_id, 0) + score
    return sorted(rrf_score.items(), key=lambda x: x[1], reverse=True)

# 向量检索和关键词检索结果融合
final = rrf_fusion([vector_results, keyword_results], k=60)

父子文档检索

在检索后处理阶段，将子块检索结果映射回父块：

from langchain.retrievers import ParentDocumentRetriever
from langchain.storage import InMemoryStore

# 子块用于搜索，父块用于生成
retriever = ParentDocumentRetriever(
    vectorstore=vectorstore,  # 子块向量库
    docstore=InMemoryStore(),  # 父块存储
    child_splitter=child_splitter,
    parent_splitter=parent_splitter,
)

最佳实践流程

1. 多路召回（Dense + BM25 + Summary）
2. RRF 融合排序（子块级）
3. Rerank 精排（Cross-Encoder）
4. 按 parent_id 去重，召回父块
5. Top-5 父块送给 LLM
🎯 总控原则
  1. 所有检索、融合、Rerank 都在子块层完成
  2. Summary 只负责"别找错地方"，不当证据
  3. 父块只在最后一步出现，用来"保证判断成立"
