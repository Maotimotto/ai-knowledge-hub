SDK

OpenAI Agents SDK 深入解析

进阶
OpenAI 官方轻量级多智能体框架 | 核心特性: Handoff 转交机制

概述

OpenAI Agents SDK（原 Swarm 框架的生产版）是 OpenAI 官方推出的轻量级多智能体框架，于 2025 年 3 月正式发布。它提供了构建 Agent 应用所需的核心原语：Agent、Runner、Tool、Guardrail 和 Handoff。

核心架构

┌──────────────────────────────────────────────────────┐ │ OpenAI Agents SDK │ │ │ │ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │ Agent A │──►│ Handoff │──►│ Agent B │ │ │ │(指令+工具)│ │ (转交) │ │(指令+工具)│ │ │ └────┬────┘ └─────────┘ └────┬────┘ │ │ │ │ │ │ ┌────▼────────────────────────────▼────┐ │ │ │ Runner（执行引擎） │ │ │ │ 循环：LLM调用 → 工具调用 → 结果组装 │ │ │ └──────────────────────────────────────┘ │ │ │ │ │ │ │ ┌────▼────┐ ┌─────▼────┐ ┌────▼─────┐ │ │ │ Tool │ │ Guardrail│ │ Tracing │ │ │ │ (工具) │ │ (护栏) │ │ (追踪) │ │ │ └─────────┘ └──────────┘ └──────────┘ │ └──────────────────────────────────────────────────────┘

核心概念

3.1 Agent

Python
from agents import Agent

agent = Agent(
    name="Weather Assistant",
    instructions="你是一个天气助手，帮助用户查询天气信息。始终用中文回复。",
    model="gpt-4o",
    tools=[get_weather, get_forecast],
    handoffs=[specialist_agent],
    output_type=WeatherReport,           # 结构化输出（Pydantic 模型）
    model_settings=ModelSettings(temperature=0.5, max_tokens=4096),
)

Agent 关键属性：

属性说明
nameAgent 名称，用于日志和追踪
instructions系统指令，可以是字符串或函数
model使用的模型名称
tools工具列表（FunctionTool 等）
handoffs可转交的目标 Agent 列表
output_type结构化输出的 Pydantic 模型
input_guardrails输入护栏列表
output_guardrails输出护栏列表

3.2 Runner（执行引擎）

Python
from agents import Agent, Runner

# 方式 1：同步执行
result = Runner.run_sync(starting_agent=agent, input="北京今天天气怎么样？")
print(result.final_output)

# 方式 2：异步执行
result = await Runner.run(starting_agent=agent, input="北京今天天气怎么样？")

# 方式 3：流式执行
result = Runner.run_streamed(starting_agent=agent, input="北京今天天气怎么样？")
async for event in result.stream_events():
    if event.type == "raw_response_event" and hasattr(event.data, 'delta'):
        print(event.data.delta, end="", flush=True)

Runner 执行循环：

  1. 将 input + instructions + tools 传给 LLM
  2. LLM 返回响应
    • 文本回复 → 返回结果
    • 工具调用 → 执行工具 → 将结果反馈给 LLM → 回到步骤 2
    • Handoff → 切换到目标 Agent → 回到步骤 1
  3. 重复直到 LLM 返回最终文本或达到最大轮次

3.4 Handoff（转交）

Python
from agents import Agent, handoff

billing_agent = Agent(
    name="Billing Agent",
    instructions="处理账单和支付相关问题。",
    tools=[check_bill, process_refund],
)

triage_agent = Agent(
    name="Triage Agent",
    instructions="""你是客服分流助手。根据用户问题：
    - 账单/支付问题 → 转交给 Billing Agent
    - 技术/故障问题 → 转交给 Technical Support""",
    handoffs=[billing_agent, technical_agent],
)

3.5 Guardrail（护栏）

Guardrail 用于在 Agent 处理前后进行输入/输出验证，确保安全性：

Python
from agents import input_guardrail, output_guardrail

@input_guardrail
async def sensitive_content_guardrail(ctx, agent, input):
    result = await Runner.run(sensitive_checker, input, context=ctx.context)
    output = result.final_output_as(SensitiveCheckOutput)
    return GuardrailFunctionOutput(
        output_info=output,
        tripwire_triggered=output.is_sensitive,
    )

safe_agent = Agent(
    name="Safe Assistant",
    instructions="你是一个安全的助手。",
    input_guardrails=[sensitive_content_guardrail],
    output_guardrails=[output_safety_guardrail],
)

优缺点

  • 优点: 官方支持、轻量简洁、Handoff机制优雅、内置追踪、结构化输出、Guardrail系统、流式支持
  • 缺点: OpenAI绑定、功能覆盖面较窄、无内置记忆、社区较小、不适合复杂图工作流

适用场景

场景说明
客服系统Triage → 专业 Agent 的 Handoff 模式
信息提取结构化输出提取结构化数据
安全对话Guardrail 确保输入输出安全
多步工作流多 Agent 协作完成复杂任务
AutoGen

AutoGen 对话式多智能体框架

进阶
微软研究院开源 | 核心特点: 对话驱动的多智能体协作

概述

AutoGen 是微软研究院开源的多智能体对话框架，核心理念是通过Agent 之间的对话来完成复杂任务。它支持灵活的对话模式——从简单的双 Agent 对话到复杂的群聊协作。

核心架构

┌──────────────────────────────────────────────┐ │ AutoGen 对话框架 │ │ │ │ ┌──────────────┐ ┌──────────────────┐ │ │ │AssistantAgent│ │ UserProxyAgent │ │ │ │ (AI 助手) │◄──►│ (人类代理/执行器) │ │ │ └──────────────┘ └──────────────────┘ │ │ │ │ │ │ ┌────▼──────────────────────▼────┐ │ │ │ GroupChat（群聊模式） │ │ │ │ Agent A ↔ Agent B ↔ Agent C │ │ │ │ ↕ GroupChatManager │ │ │ └────────────────────────────────┘ │ └──────────────────────────────────────────────┘

AssistantAgent

Python
import autogen

assistant = autogen.AssistantAgent(
    name="assistant",

UserProxyAgent

Python
user_proxy = autogen.UserProxyAgent(
    name="user_proxy",
    human_input_mode="TERMINATE",  # "ALWAYS" | "NEVER" | "TERMINATE"
    max_consecutive_auto_reply=10,
    code_execution_config={"work_dir": "coding", "use_docker": True, "timeout": 120},
)

human_input_mode 说明：

模式说明
ALWAYS每轮都请求人类输入
TERMINATE仅在对话终止时请求输入
NEVER完全自动，不请求人类输入

CrewAI

CrewAI 多智能体协作框架

进阶
开源 | 核心特点: 角色驱动的声明式多智能体协作

概述

CrewAI 是一个开源的多智能体协作框架，灵感来自真实世界的团队协作模式。它将 AI Agent 建模为具有角色（Role）、目标（Goal）和背景故事（Backstory）的"crew 成员"，通过分工协作完成复杂任务。

核心架构

┌─────────────────────────────────────┐ │ Crew（团队） │ │ ┌──────────┐ ┌──────────┐ │ │ │ Agent A │ │ Agent B │ ... │ │ │ (角色+目标)│ │ (角色+目标)│ │ │ └────┬─────┘ └────┬─────┘ │ │ │ │ │ │ ┌────▼─────┐ ┌────▼─────┐ │ │ │ Task 1 │ │ Task 2 │ ... │ │ │(描述+期望) │ │(描述+期望) │ │ │ └──────────┘ └──────────┘ │ │ │ │ Process: Sequential / Hierarchical │ └─────────────────────────────────────┘

核心概念

Agent（智能体）

Python
from crewai import Agent

researcher = Agent(
    role="高级研究分析师",
    goal="发现关于 {topic} 的最新洞见",
    backstory="你是一位经验丰富的研究分析师，擅长从海量信息中提取关键洞见。",
    verbose=True,
    allow_delegation=False,
    tools=[search_tool, scrape_tool],
    llm="gpt-4o",
    memory=True,
)

Task（任务）

Python
from crewai import Task

research_task = Task(
    description="对 {topic} 进行全面研究，分析最新趋势、关键参与者和技术发展。",
    expected_output="一份包含 3 个关键发现的段落，附带数据支持",
    agent=researcher,
    output_file="research_report.md",
    context=[prior_task],
)

Crew（团队）+ Process（执行流程）

Python
from crewai import Crew, Process

crew = Crew(
    agents=[researcher, writer, editor],
    tasks=[research_task, writing_task, editing_task],
    process=Process.sequential,    # 顺序执行
    # process=Process.hierarchical,  # 层级式（Manager Agent 协调）
    memory=True, verbose=True,
)
result = crew.kickoff(inputs={"topic": "2025年大语言模型发展趋势"})

Process 类型：

流程类型说明
Process.sequential任务按顺序依次执行，前一个任务的输出作为后续任务的上下文
Process.hierarchical由 Manager Agent 自动分配和协调任务

记忆系统

CrewAI 内置三层记忆：

  • Long-term Memory: 跨 session 持久化到 SQLite
  • Short-term Memory: 当前 session 内的上下文
  • Entity Memory: 记录涉及的人物/组织等实体

优缺点

  • 优点: 直觉化角色设计、内置三层记忆、丰富工具生态、Flows支持、低学习曲线
  • 缺点: 大规模场景受限、调试困难、模型依赖、企业级特性不足

适用场景

场景说明
内容生产研究→写作→审核的流水线
数据分析数据收集→清洗→分析→报告
市场调研竞品分析→趋势总结→策略建议
代码开发需求分析→编码→测试→文档
MetaGPT

MetaGPT 软件开发智能体框架

进阶
DeepWisdom 开源 | 核心特点: 将软件公司 SOP 映射为多智能体协作

概述

MetaGPT 是一个将人类软件公司运作流程（SOP）映射到多智能体协作的框架。核心理念：让 AI Agent 像真实软件公司的员工一样，按照标准流程协作完成软件开发。

核心架构

┌─────────────────────────────────────────────────┐ │ MetaGPT 软件公司 │ │ │ │ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │ PM │ │Architect │ │Engineer │ │ │ │产品经理 │──►│ 架构师 │──►│ 工程师 │ │ │ └─────────┘ └─────────┘ └─────────┘ │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │PRD文档 │ │系统设计 │ │代码实现 │ │ │ └─────────┘ └─────────┘ └─────────┘ │ │ │ │ │ ┌─────▼──────┐ │ │ │ QA │ │ │ │ 测试工程师 │ │ │ └────────────┘ │ │ │ │ ┌──────────────────────────────────────┐ │ │ │ Environment（共享环境/消息总线） │ │ │ │ Message Pool ←→ Subscription 机制 │ │ │ └──────────────────────────────────────┘ │ └─────────────────────────────────────────────────┘

核心概念

SOP 驱动的工作流

用户需求 → PM(产品需求) → Architect(技术设计) → Engineer(代码实现) → QA(测试验证) ↓ ↓ ↓ ↓ PRD.md design.md code files test results 数据接口 API 设计 单元测试 bug report

内置角色

角色职责输出
ProductManager需求分析、产品规划PRD（产品需求文档）
Architect技术选型、系统设计系统设计文档、API 设计
ProjectManager项目管理、任务拆解任务列表、进度跟踪
Engineer代码实现源代码文件
QAEngineer测试用例、代码审查测试代码、Bug 报告

消息机制

Agent 之间通过消息订阅机制通信：

Agent A 发布消息 → Message Pool → Agent B（已订阅该消息类型）收到并处理

  • 优点: 工程化流程、角色专业化、完整开发链路、代码质量好、支持增量开发
  • 缺点: Token消耗大、灵活性不足（仅适合软件开发）、速度慢、配置复杂
