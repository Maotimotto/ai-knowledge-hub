N-Shot Prompting (Zero/One/Few-shot) ⭐基础

全局定位

N-Shot Prompting 是 Agent 开发知识体系中的基础技能层，通过给模型展示示例来引导输出，是所有 Prompt 工程技术的起点。

├── 14-高级Prompt模式 ← 推理层：CoT/ReAct 基于此
└── 11-Agent框架对比 ← 框架的 prompt 设计

学习价值：N-Shot 是 Prompt Engineering 的基础。3-8 个示例 + CoT 推理过程的组合，是提升 Agent 输出质量的最实用方法。

来源: 知识星球/AI基础的概念/prompt提示词工程/
整理时间: 2026-05-30

核心概念

通过给模型展示 0/1/多个 示例，引导模型理解任务意图的技术。底层原理是LLM的上下文学习（In-Context Learning）能力。

三种模式

Zero-shot: 直接下指令，靠模型预训练知识。适用：通用任务如"总结这篇文章"。

One-shot: 给一个模板定调子。

输入: 餐厅 -> 输出: CYBER-EAT-01
输入: 图书馆 -> 输出: ?

Few-shot: 给多个示例对齐格式和逻辑。适用：特定格式输出、冷门领域。

N-Shot vs Fine-tuning

N-Shot: 临时抱佛脚，改Prompt不改参数，省钱快速
Fine-tuning: 基因改造，大量数据重训练，贵慢但强

最佳实践

样本数量：3-8个为过多会费Token且可能"复读机"
样本多样性：覆盖典型case和边界case
结合CoT：在示例中加入推理过程效果更佳

面试高频问题

Q: Few-shot越多越好？ 不是。Context Window有限，3-8个边际效应递减。

Q: Few-shot效果不好怎么办？ 引入Chain of Thought (CoT)，不仅给结果还给解题过程。

思维链 CoT (Chain of Thought) ⭐基础

全局定位

CoT 是 Agent 开发知识体系中的推理基础，通过引导模型展示中间推理步骤来提升复杂任务的准确性，是 ReAct、ToT 等高级推理模式的核心组件。
08-提示词工程
├── 01-N-Shot-Prompting ← 示例引导
├── 02-思维链CoT ✅ ← 推理引导
└── 03-角色定义Prompting ← 身份引导

14-高级Prompt模式
├── ReAct = CoT + Action
├── Reflexion = CoT + 反思
└── ToT = CoT 的树状扩展

学习价值：CoT 是 70B+ 参数模型的涌现能力，"Let's think step by step" 是最简单有效的推理增强技巧。理解 CoT 是掌握所有高级 Agent 推理模式的前提。

来源: 知识星球/AI基础的概念/prompt提示词工程/
整理时间: 2026-05-30

核心概念

CoT是在Few-shot示例中，不仅给出"问题-答案"，还详细写出中间推理过程，诱导模型进行逻辑推理。

核心公式: CoT = Few-shot + 逻辑过程

普通Few-shot只给答案（死记硬背）
CoT边写边推导（学会逻辑）

为什么需要CoT

LLM本质是概率预测，不强制写步骤会"看一眼就猜答案"
解决多步骤逻辑中"一步错步步错"的问题
是涌现能力，通常70B+参数时效果显著

实战场景

复杂财务计算：要求列出每一步公式
代码纠错：先分析Bug成因再修复
多步决策：退货→检查保修→查库存→生成退货单

Zero-shot CoT

不需要示例，Prompt末尾加"魔法咒语"：

Let's think step by step.

代码示例

# CoT思维链
cot = """
Q: 盒子里有5个球，拿走2个，放进4个，现在有15个。最初有几个？
A: 让我们一步步思考：
1. 现有15个。
2. 逆向：放进4个前有 15-4=11个。
3. 拿走2个前有 11+2=13个。
答案是13。
"""

面试高频问题

Q: CoT在7B小模型上有效吗？ 效果不佳甚至有副作用，CoT是涌现能力，70B+才表现强。

Q: 什么是Zero-shot CoT？ Prompt末尾加"Let's think step by step"，无需示例即提升推理准确度。

角色定义 Prompting (Role Prompting) ⭐基础

全局定位

角色定义是 Agent 开发知识体系中的身份锚定技术，通过指定 AI 的身份、背景和专业领域来约束输出风格与知识边界，是所有 Agent 框架 system prompt 设计的核心。
08-提示词工程
├── 01-N-Shot-Prompting ← 示例引导
├── 02-思维链CoT ← 推理引导
└── 03-角色定义Prompting ✅ ← 身份引导

11-Agent框架对比
├── CrewAI: role + goal + backstory
├── AutoGen: system_message
├── MetaGPT: profile + goal + constraints
└── Agents SDK: instructions

学习价值：角色定义是 Agent 开发的第一步——每个 Agent 都需要一个清晰的 system prompt。掌握"你是谁+你要做什么+你不能做什么"三要素，能显著提升 Agent 输出质量。

来源: 知识星球/AI基础的概念/prompt提示词工程/
整理时间: 2026-05-30

核心概念

通过明确指定AI的身份、背景和专业领域，约束输出风格与知识边界。本质是概率锚定——缩小模型在概率空间中的搜索范围。

角色设定三要素

你是谁: 专业背景、经验年限、性格特征
你要做什么: 明确工作目标和输出要求
你不能做什么: 禁止行为、安全边界

实战场景

专业顾问系统: 医疗/法律RAG中设定"严谨合规审查员"
性格化IP: 游戏NPC设定"傲娇少女"或"毒舌教练"
复杂任务拆解: 设定"资深架构师"，先输出架构图再写代码

代码示例

# 带角色认定
prompt = """
### System:
你是一位20年经验的Python资深架构师，性格严谨毒舌。
重视PEP8和安全性。回复必须包含：吐槽点、改进建议、重构代码。

### User:
评价: def f(x): return x*0.1
"""
# 输出: "【吐槽】函数名f是认真的吗？
#        【建议】命名要有意义，加类型标注
#        【代码】def calculate_tax(amount: float) -> float: ..."

与其他技术的关系

vs Few-shot: 角色认定定调子，Few-shot给例子，结合效果最好
vs System Prompt: 角色认定通常写在System Prompt中

最佳实践

关键约束原则：只保留决定性影响的背景、技能和禁忌
防止出戏：System Prompt定义角色 + User Prompt分隔符引导

面试高频问题

Q: 角色设定越详细越好？ 过犹不及。过长占Token且导致注意力分散（Loss of Middle）。

Q: 如何防止模型出戏？ System Prompt锁身份 + User Prompt分隔符 + Frequency Penalty参数。
