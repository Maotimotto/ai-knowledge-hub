1. 概述

ReAct（Reasoning + Acting）由 Yao et al. (2022) 提出，将推理（Thought）与行动（Action）交织在一个循环中，让 LLM 能够像人类一样"边想边做"。

论文: ReAct: Synergizing Reasoning and Acting in Language Models (ICLR 2023)

2. 核心思想

传统方法存在两种极端：

  • 纯推理（Chain-of-Thought）: 只思考不行动，无法获取外部信息
  • 纯行动（Act-only）: 只执行不推理，容易陷入错误循环

ReAct 将两者结合：

┌─────────────────────────────────────────────┐
│              ReAct 循环                      │
│                                             │
│   Thought → Action → Observation → Thought  │
│     ↑                              │        │
│     └──────────────────────────────┘        │
│                                             │
│   Thought:   推理当前状态，规划下一步         │
│   Action:    调用工具/执行操作               │
│   Observation: 获取操作结果                  │
└─────────────────────────────────────────────┘

3. 标准 ReAct 提示格式

Question: 奥巴马的妻子出生在哪个城市？

Thought 1: 我需要搜索奥巴马的妻子是谁。
Action 1: Search[奥巴马的妻子]
Observation 1: 米歇尔·奥巴马，1964年1月17日出生于伊利诺伊州芝加哥。

Thought 2: 米歇尔·奥巴马出生在芝加哥。
Action 2: Finish[芝加哥]
Observation 2: 结束。

4.2 自定义 ReAct Agent（LangGraph）

from langgraph.graph import StateGraph, END
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from typing import TypedDict, Annotated, Sequence
import operator

class AgentState(TypedDict):
    messages: Annotated[Sequence, operator.add]
    intermediate_steps: list

def reasoning_node(state: AgentState) -> AgentState:
    """Thought: 推理节点 — 分析当前状态，决定下一步"""
    messages = state["messages"]
    steps = state.get("intermediate_steps", [])

    # 构造推理 prompt
    scratchpad = ""
    for action, observation in steps:
        scratchpad += f"Action: {action.tool}({action.tool_input})\n"
        scratchpad += f"Observation: {observation}\n"

    prompt = f"""你是一个 ReAct Agent。根据问题和历史步骤推理。

{scratchpad}

请输出下一步行动（JSON格式）:
{{"action": "tool_name", "action_input": "input"}}
或直接回答: {{"action": "finish", "action_input": "最终答案"}}"""

    response = llm.invoke([messages[-1], HumanMessage(content=prompt)])
    return {"messages": [response]}

def action_node(state: AgentState) -> AgentState:
    """Action + Observation: 执行工具并观察结果"""
    last_msg = state["messages"][-1]
    action = parse_action(last_msg.content)  # 解析 JSON

    if action["action"] == "finish":
        return {"messages": [AIMessage(content=action["action_input"])]}

    # 执行工具
    tool = tool_map[action["action"]]
    result = tool.invoke(action["action_input"])

    return {
        "intermediate_steps": [(action, result)]
    }

def should_continue(state: AgentState) -> str:
    last = state["messages"][-1]
    if isinstance(last, AIMessage) and "finish" not in last.content.lower():
        return "reason"
    return END

# 构建 LangGraph
graph = StateGraph(AgentState)
graph.add_node("reason", reasoning_node)
graph.add_node("act", action_node)
graph.set_entry_point("reason")
graph.add_conditional_edges("reason", should_continue, {"reason": "act", END: END})
graph.add_edge("act", "reason")

app = graph.compile()

from langchain_core.tools import tool
from langchain_openai import ChatOpenAI
from langgraph.prebuilt import create_react_agent

@tool
def search_wikipedia(query: str) -> str:
    """搜索维基百科获取信息"""
    import requests
    resp = requests.get(f"https://zh.wikipedia.org/api/rest_v1/page/summary/{query}")
    return resp.json().get("extract", "未找到相关信息")

@tool
def calculator(expression: str) -> str:
    """计算数学表达式"""
    try:
        return str(eval(expression))
    except Exception as e:
        return f"计算错误: {e}"

@tool
def python_repl(code: str) -> str:
    """执行 Python 代码"""
    import subprocess
    result = subprocess.run(
        ["python3", "-c", code], capture_output=True, text=True, timeout=10
    )
    return result.stdout or result.stderr

# 使用 LangGraph 内置 ReAct Agent
llm = ChatOpenAI(model="gpt-4o", temperature=0)
agent = create_react_agent(llm, [search_wikipedia, calculator, python_repl])

result = await agent.ainvoke({

})

7. 最佳实践

  1. 限制迭代次数: 设置 max_iterations=8-15
  2. 工具描述要精确: 工具的 docstring 直接影响 Agent 选择
  3. 加入回退机制: 检测循环并强制终止
  4. 压缩历史: 当中间步骤过多时，用摘要替代完整历史

1. 概述

Plan-and-Execute 模式将任务分解为规划（Plan）和执行（Execute）两个阶段，由一个 Planner 负责制定计划，一个 Executor 负责逐步执行，实现"先想清楚再动手"。

论文: Plan-and-Solve Prompting (Wang et al., 2023) 和 BabyAGI (Nakajima, 2023)

2. 与 ReAct 的核心区别

ReAct 模式（边想边做）:
  Thought → Action → Obs → Thought → Action → Obs → ...
  特点: 无全局规划，每步决定下一步

Plan-and-Execute 模式（先想后做）:
  ┌──────────────────────────────────────┐
  │  Phase 1: Plan                       │
  │  输入 → Planner → [Step1, Step2, ...]│
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │  Phase 2: Execute                    │
  │  Step1 → Executor → Result1          │
  │  Step2 → Executor → Result2          │
  │  ...                                 │
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │  Phase 3: Synthesize                 │
  │  所有结果 → Synthesizer → 最终答案    │
  └──────────────────────────────────────┘

4.1 完整实现

from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated, List, Union
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage
import operator

# ============ 状态定义 ============
class PlanExecuteState(TypedDict):
    input: str                    # 用户输入
    plan: List[str]               # 计划步骤列表
    current_step: int             # 当前执行到第几步
    past_steps: Annotated[List[tuple], operator.add]  # (步骤, 结果) 历史
    response: str                 # 最终响应

# ============ Planner 节点 ============
planner_prompt = """你是一个任务规划专家。给定一个目标，将其分解为可执行的步骤。

目标: {goal}

请输出一个 JSON 格式的计划:
{{"steps": ["步骤1描述", "步骤2描述", "步骤3描述", ...]}}

要求:
1. 每个步骤应该是独立可执行的
2. 步骤之间有清晰的依赖关系
3. 总步骤数不超过 10 步
"""

def plan_node(state: PlanExecuteState) -> dict:
    """生成执行计划"""
    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    response = llm.invoke([
        SystemMessage(content=planner_prompt.format(goal=state["input"]))
    ])
    plan = parse_json(response.content)["steps"]
    return {"plan": plan, "current_step": 0}

# ============ Executor 节点 ============
executor_prompt = """你是一个任务执行器。根据当前步骤和历史结果执行任务。

原始目标: {goal}

历史执行结果:
{history}

当前需要执行的步骤: {step}

请执行这个步骤，输出结果。如果有可用工具，请调用工具。"""

def execute_node(state: PlanExecuteState) -> dict:
    """执行当前步骤"""
    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    plan = state["plan"]
    step_idx = state["current_step"]

    if step_idx >= len(plan):
        return {"response": "所有步骤已完成"}

    current = plan[step_idx]
    history = "\n".join(
        f"- {s}: {r}" for s, r in state.get("past_steps", [])
    )

    response = llm.invoke([
        HumanMessage(content=executor_prompt.format(
            goal=state["input"], history=history, step=current
        ))
    ])

    return {
        "past_steps": [(current, response.content)],
        "current_step": step_idx + 1
    }

# ============ Re-planner 节点 ============
replanner_prompt = """你是计划审查员。根据已执行的步骤，决定是否需要修改剩余计划。

原始目标: {goal}
当前计划: {plan}
已执行步骤: {past_steps}

选项:
1. 继续执行剩余计划 - 输出 {{"action": "continue"}}
2. 修改计划 - 输出 {{"action": "replan", "new_steps": [...]}}
3. 直接给出答案 - 输出 {{"action": "finish", "answer": "..."}}
"""

def replan_node(state: PlanExecuteState) -> dict:
    """审查并可能调整计划"""
    llm = ChatOpenAI(model="gpt-4o", temperature=0)
    response = llm.invoke([
        HumanMessage(content=replanner_prompt.format(
            goal=state["input"],
            plan=state["plan"][state["current_step"]:],
            past_steps=state.get("past_steps", [])
        ))
    ])
    decision = parse_json(response.content)

    if decision["action"] == "finish":
        return {"response": decision["answer"]}
    elif decision["action"] == "replan":
        return {"plan": decision["new_steps"], "current_step": 0}
    return {}

# ============ 条件路由 ============
def should_end(state: PlanExecuteState) -> str:
    if state.get("response"):
        return END
    if state["current_step"] >= len(state["plan"]):
        return "replan"
    return "replan"  # 每步执行后都检查是否需要重新规划

def after_replan(state: PlanExecuteState) -> str:
    if state.get("response"):
        return END
    return "execute"

# ============ 构建图 ============
graph = StateGraph(PlanExecuteState)
graph.add_node("plan", plan_node)
graph.add_node("execute", execute_node)
graph.add_node("replan", replan_node)

graph.set_entry_point("plan")
graph.add_edge("plan", "execute")
graph.add_conditional_edges("execute", should_end, {"replan": "replan", END: END})
graph.add_conditional_edges("replan", after_replan, {"execute": "execute", END: END})

app = graph.compile()

# ============ 运行 ============
result = app.invoke({
    "input": "帮我调研2024年大语言模型的最新进展，并写一份200字的总结"
})
print(result["response"])

  1. 计划粒度适中: 步骤不要太粗也不要太细

1. 概述

Reflexion（Shinn et al., 2023）让 Agent 在执行任务后进行自我反思，将失败经验转化为语言化的记忆，指导后续尝试。核心理念："从错误中学习"。

论文: Reflexion: Language Agents with Verbal Reinforcement Learning (NeurIPS 2023)

2. 核心思想

传统 Agent 的问题：执行失败后重试，仍会犯同样的错误。

Reflexion 的解法：

传统模式:
  尝试1: 失败 → 重试 → 失败 → 重试 → 失败（无记忆）

Reflexion 模式:
  尝试1: 失败 → 反思: "我错在哪" → 存入记忆
  尝试2: 读取记忆 + 重试 → 改进 → 失败 → 反思 → 存入记忆
  尝试3: 读取所有反思 + 重试 → 成功 ✓

4.1 完整实现

from langgraph.graph import StateGraph, END
from typing import TypedDict, List, Optional
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

class ReflexionState(TypedDict):
    task: str                          # 原始任务
    attempt: int                       # 当前尝试次数
    max_attempts: int                  # 最大尝试次数
    trajectory: str                    # 当前执行轨迹
    result: str                        # 执行结果
    is_correct: bool                   # 是否正确
    reflections: List[str]             # 历次反思记录
    best_result: Optional[str]         # 最佳结果

llm = ChatOpenAI(model="gpt-4o", temperature=0)

# ============ Actor: 执行任务 ============
def actor_node(state: ReflexionState) -> dict:
    reflections = "\n".join(f"- {r}" for r in state.get("reflections", []))
    prompt = f"""你是一个智能助手。请完成以下任务。

任务: {state["task"]}

{"历史反思（请避免重复这些错误）:" + chr(10) + reflections if reflections else ""}

请仔细思考并执行任务。"""

    response = llm.invoke([HumanMessage(content=prompt)])
    return {
        "trajectory": response.content,
        "attempt": state["attempt"] + 1
    }

# ============ Evaluator: 评估结果 ============
def evaluator_node(state: ReflexionState) -> dict:
    prompt = f"""评估以下任务的执行结果是否正确。

任务: {state["task"]}
执行结果: {state["trajectory"]}

请判断结果是否正确，输出 JSON:
{{"is_correct": true/false, "score": 0-100, "feedback": "简要评价"}}"""

    response = llm.invoke([HumanMessage(content=prompt)])
    eval_result = parse_json(response.content)

    return {
        "is_correct": eval_result["is_correct"],
        "result": state["trajectory"]
    }

# ============ Reflector: 自我反思 ============
def reflector_node(state: ReflexionState) -> dict:
    prompt = f"""你之前的执行失败了，请深入反思原因。

任务: {state["task"]}
你的回答: {state["trajectory"]}
评估反馈: 结果不正确

请反思:
1. 哪里出错了？
2. 为什么出错？
3. 下次应该如何改进？

输出一段简洁的反思（2-3句话）。"""

    response = llm.invoke([HumanMessage(content=prompt)])
    reflections = state.get("reflections", []) + [response.content]

    return {"reflections": reflections}

# ============ 路由 ============
def after_evaluate(state: ReflexionState) -> str:
    if state["is_correct"]:
        return END
    if state["attempt"] >= state["max_attempts"]:
        return END
    return "reflect"

def after_reflect(state: ReflexionState) -> str:
    return "actor"

# ============ 构建图 ============
graph = StateGraph(ReflexionState)
graph.add_node("actor", actor_node)
graph.add_node("evaluate", evaluator_node)
graph.add_node("reflect", reflector_node)

graph.set_entry_point("actor")
graph.add_edge("actor", "evaluate")
graph.add_conditional_edges("evaluate", after_evaluate, {
    END: END, "reflect": "reflect"
})
graph.add_conditional_edges("reflect", after_reflect, {"actor": "actor"})

app = graph.compile()

# ============ 运行 ============
result = app.invoke({
    "task": "用 Python 实现一个 LRU Cache，要求 O(1) 的 get 和 put 操作",
    "attempt": 0,
    "max_attempts": 3,
    "reflections": [],
    "is_correct": False,
    "trajectory": "",
    "result": "",
    "best_result": None
})

import chromadb
from langchain_openai import OpenAIEmbeddings

class ReflexionMemory:
    """基于向量数据库的反思记忆"""

    def __init__(self):
        self.client = chromadb.Client()
        self.collection = self.client.create_collection("reflections")
        self.embeddings = OpenAIEmbeddings()

    def store(self, task: str, reflection: str, outcome: str):
        """存储反思"""
        self.collection.add(
            documents=[reflection],
            metadatas=[{"task": task, "outcome": outcome}],
            ids=[f"ref_{self.collection.count()}"]
        )

    def retrieve(self, task: str, k: int = 3) -> List[str]:
        """检索相关反思"""
        results = self.collection.query(
            query_texts=[task],
            n_results=k
        )
        return results["documents"][0] if results["documents"] else []

# 在 reflector_node 中使用
memory = ReflexionMemory()

def reflector_with_memory(state: ReflexionState) -> dict:
    # 检索相关历史反思
    similar_reflections = memory.retrieve(state["task"])

    prompt = f"""基于当前任务和相关历史经验进行反思。

任务: {state["task"]}
执行结果: {state["trajectory"]}
相关历史经验: {similar_reflections}

请输出改进反思。"""

    response = llm.invoke([HumanMessage(content=prompt)])
    memory.store(state["task"], response.content, "failure")

    reflections = state.get("reflections", []) + [response.content]
    return {"reflections": reflections}

1. 概述

Tree-of-Thoughts（ToT）由 Yao et al. (2023) 提出，将推理过程建模为一棵思维树，允许 LLM 在多个推理路径上进行搜索、评估和回溯，突破了 Chain-of-Thought 的线性思维限制。

论文: Tree of Thoughts: Deliberate Problem Solving with Large Language Models (NeurIPS 2023)

2. 核心思想

Chain-of-Thought（线性思维）:
  Thought1 → Thought2 → Thought3 → Answer
  问题: 一旦走错，无法回头

Tree-of-Thoughts（树状思维）:
                    Thought1
                   /    |    \
              T2_a      T2_b      T2_c        ← 推理分支
             /   \       |       /   \
          T3_a  T3_b   T3_c   T3_d  T3_e     ← 更多分支
           ✓     ✗      ✓      ✗     ✓       ← 评估剪枝
          选中                    选中  选中

  关键: 探索多条路径，评估后选择最优路径继续

3. ToT vs CoT vs Self-Consistency

┌───────────────────────────────────────────────────────────┐
│  CoT (线性):                                              │
│  Q → T1 → T2 → T3 → A                                    │
│                                                           │
│  Self-Consistency (并行线性):                              │
│  Q → T1a → T2a → A1                                       │
│  Q → T1b → T2b → A2  → 投票 → A_final                    │
│  Q → T1c → T2c → A3                                       │
│                                                           │
│  Tree-of-Thoughts (树搜索):                                │
│  Q → T1 → [评估] → 选择最优 → T2 → [评估] → ... → A       │
│     ↘ T1' → [评估] →                                       │
│       ↘ T1'' → [淘汰]                                      │
│                                                           │
│  关键区别: ToT 在每一步都做评估和选择，而非生成后投票       │
└───────────────────────────────────────────────────────────┘

4. 三大组件

┌─────────────────────────────────────────────┐
│  1. Thought Generator（思维生成器）          │
│     在每个节点生成多个候选思维               │
│     策略:                                    │
│     - Sample: 采样 k 个独立思维              │
│     - Propose: 一次性提出 k 个思维           │
├─────────────────────────────────────────────┤
│  2. State Evaluator（状态评估器）            │
│     评估每个思维的"前景"                     │
│     方法:                                    │
│     - Value: 直接给价值打分                  │
│     - Vote: 对比多个思维投票                 │
├─────────────────────────────────────────────┤
│  3. Search Algorithm（搜索算法）             │
│     决定如何遍历思维树                       │
│     - BFS: 广度优先搜索                     │
│     - DFS: 深度优先搜索                     │
└─────────────────────────────────────────────┘

5. BFS vs DFS 搜索策略

5.1 BFS（广度优先）

层级 0:        [根节点]
               /  |  \
层级 1:     [A]  [B]  [C]      ← 评估: A=0.8, B=0.3, C=0.7
              保留A和C，剪枝B
             / \      |
层级 2:   [A1] [A2] [C1]       ← 评估: A1=0.9, A2=0.4, C1=0.6
            保留A1，剪枝其余
            |
层级 3:   [A1a]                  ← 最终答案

适用: 每层候选少，需要全局视角

5.2 DFS（深度优先）

                    [根]
                   / | \
                [A] [B] [C]
               /
            [A1] ← 评估: 前景好，继续深入
            /
         [A1a] ← 评估: 前景不好，回溯!
            ↩ 回到 [A]
              \
            [A2] ← 评估: 前景好，继续
            /
         [A2a] ← 找到答案！

适用: 解空间深，需要探索到底

from langchain_openai import ChatOpenAI
from typing import List, Tuple
from dataclasses import dataclass, field
import heapq

@dataclass
class ThoughtNode:
    """思维树节点"""
    content: str
    depth: int
    score: float = 0.0
    parent: 'ThoughtNode' = None
    children: List['ThoughtNode'] = field(default_factory=list)

    def __lt__(self, other):
        return self.score > other.score  # 最大堆

class TreeOfThoughts:
    def __init__(
        self,
        llm: ChatOpenAI,
        bfs_width: int = 3,       # BFS 每层保留的节点数
        max_depth: int = 5,       # 最大深度
        threshold: float = 0.5,   # 评估阈值
    ):
        self.llm = llm
        self.bfs_width = bfs_width
        self.max_depth = max_depth
        self.threshold = threshold

    def generate_thoughts(self, problem: str, current_path: List[str], k: int = 3) -> List[str]:
        """生成 k 个候选思维"""
        path_str = " → ".join(current_path) if current_path else "（开始）"
        prompt = f"""问题: {problem}

当前推理路径: {path_str}

请提出 {k} 个不同的下一步推理思路，每个思路只写1-2句话。
输出格式（每行一个）:
1. 思路1
2. 思路2
3. 思路3"""

        response = self.llm.invoke([{"role": "user", "content": prompt}])
        thoughts = parse_numbered_list(response.content)
        return thoughts[:k]

    def evaluate_thought(self, problem: str, thought: str, path: List[str]) -> float:
        """评估一个思维的价值 (0-1)"""
        path_str = " → ".join(path + [thought])
        prompt = f"""问题: {problem}

推理路径: {path_str}

请评估这条推理路径的前景（0-100分）。考虑:
1. 是否在朝正确方向前进？
2. 逻辑是否合理？
3. 距离答案还有多远？

只输出一个数字。"""

        response = self.llm.invoke([{"role": "user", "content": prompt}])
        try:
            score = float(response.content.strip()) / 100.0
        except:
            score = 0.5
        return score

    def solve_bfs(self, problem: str) -> str:
        """BFS 搜索"""
        root = ThoughtNode(content="ROOT", depth=0, score=1.0)
        current_nodes = [root]

        for depth in range(self.max_depth):
            all_candidates = []

            for node in current_nodes:
                path = self._get_path(node)
                thoughts = self.generate_thoughts(problem, path)

                for thought in thoughts:
                    score = self.evaluate_thought(problem, thought, path)
                    child = ThoughtNode(
                        content=thought,
                        depth=depth + 1,
                        score=score,
                        parent=node
                    )
                    node.children.append(child)

                    if score >= self.threshold:
                        all_candidates.append(child)

            if not all_candidates:
                break

            # 保留得分最高的 bfs_width 个
            all_candidates.sort(key=lambda n: n.score, reverse=True)
            current_nodes = all_candidates[:self.bfs_width]

            # 检查是否有"足够好"的叶子节点
            best = current_nodes[0]
            if best.score > 0.9:
                return self._collect_answer(best)

        # 返回最佳路径
        best = max(current_nodes, key=lambda n: n.score)
        return self._collect_answer(best)

    def solve_dfs(self, problem: str, node: ThoughtNode = None, path: List[str] = None) -> str:
        """DFS 搜索"""
        if node is None:
            node = ThoughtNode(content="ROOT", depth=0, score=1.0)
            path = []

        if node.depth >= self.max_depth:
            return self._collect_answer(node)

        thoughts = self.generate_thoughts(problem, path)

        for thought in thoughts:
            score = self.evaluate_thought(problem, thought, path)

            if score < self.threshold:
                continue  # 剪枝

            child = ThoughtNode(
                content=thought, depth=node.depth + 1,
                score=score, parent=node
            )
            node.children.append(child)

            result = self.solve_dfs(problem, child, path + [thought])
            if result:
                return result

        return None

    def _get_path(self, node: ThoughtNode) -> List[str]:
        path = []
        while node.parent:
            path.append(node.content)
            node = node.parent
        return list(reversed(path))

    def _collect_answer(self, node: ThoughtNode) -> str:
        path = self._get_path(node)
        return "\n".join(f"Step {i+1}: {t}" for i, t in enumerate(path))

9. 成本与优化

Token 消耗估算

ToT (BFS, width=3, depth=4):
  每层生成: 3 × 3 = 9 个思维 × 评估
  总 LLM 调用: ~36 次（生成18 + 评估18）
  Token: ~36 × 500 = 18,000 tokens

对比:
  CoT: 1 次调用, ~500 tokens
  Self-Consistency (5次): 5 次调用, ~2,500 tokens

ToT 成本约是 CoT 的 36 倍！

优化策略

  1. 自适应宽度: 根据问题难度动态调整
  2. 快速评估器: 用小模型评估，大模型生成
  3. 缓存: 相似思维路径复用评估结果
  4. 阈值剪枝: 严格的阈值减少无效探索

3. MCTS 基础回顾

蒙特卡洛树搜索的四个阶段：

               ① 选择 (Selection)
                    │
                    ▼
               [Root Node]
              /     |     \
           [A]    [B]    [C]
          /  \     |
        [A1] [A2] [B1]     ② 扩展 (Expansion)
                            选择最有前景的节点
                            扩展一个新子节点
                    │
                    ▼
                [New Node]
                    │
                    ▼
            ③ 模拟 (Simulation)
            从新节点开始随机/启发式
            模拟到终态，获得奖励
                    │
                    ▼
            ④ 回传 (Backpropagation)
            将奖励沿路径回传，
            更新节点统计信息

UCT 公式（选择策略）

UCT(i) = Q(i)/N(i) + c × √(ln(N(parent)) / N(i))

其中:
  Q(i) = 节点 i 的累计奖励
  N(i) = 节点 i 的访问次数
  c    = 探索常数（通常 √2）

第一项: 利用（选择高奖励的节点）
第二项: 探索（选择访问少的节点）

6.1 核心数据结构

from dataclasses import dataclass, field
from typing import List, Optional, Dict, Any
import math
import random

@dataclass
class LATSNode:
    """LATS 树节点"""
    state: str                          # 当前状态描述
    action: Optional[str] = None        # 导致此状态的行动
    parent: Optional['LATSNode'] = None
    children: List['LATSNode'] = field(default_factory=list)

    # MCTS 统计
    visit_count: int = 0
    total_value: float = 0.0
    prior_score: float = 0.5            # LLM 先验评分

    # LATS 特有
    reflection: str = ""                # 语言化反思
    environment_feedback: str = ""      # 环境反馈
    is_terminal: bool = False
    depth: int = 0

    @property
    def avg_value(self) -> float:
        return self.total_value / self.visit_count if self.visit_count > 0 else 0.0

    def uct_score(self, c: float = 1.414) -> float:
        """计算 UCT 分数"""
        if self.visit_count == 0:
            return float('inf')

        exploitation = self.avg_value
        exploration = c * math.sqrt(
            math.log(self.parent.visit_count) / self.visit_count
        )
        prior = self.prior_score / (1 + self.visit_count)

        return exploitation + exploration + prior

6.2 LATS 引擎

from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

class LATSEngine:
    def __init__(
        self,
        llm: ChatOpenAI,
        tools: List[Any],
        max_iterations: int = 20,
        max_children: int = 3,
        max_depth: int = 10,
    ):
        self.llm = llm
        self.tools = {t.name: t for t in tools}
        self.max_iterations = max_iterations
        self.max_children = max_children
        self.max_depth = max_depth

    def solve(self, problem: str) -> str:
        """主入口: 用 LATS 求解问题"""
        root = LATSNode(state=f"问题: {problem}", depth=0)

        for i in range(self.max_iterations):
            # 1. Selection: 选择最佳叶子节点
            leaf = self._select(root)

            # 2. 检查是否已解决
            if leaf.is_terminal and self._is_solution(leaf):
                return self._extract_solution(leaf)

            # 3. Expansion: 扩展子节点
            children = self._expand(leaf, problem)

            if not children:
                continue

            # 4. Simulation: 模拟评估
            for child in children:
                value = self._simulate(child, problem)

                # 5. Backpropagation: 回传
                self._backpropagate(child, value)

        # 返回最佳路径
        best_leaf = self._get_best_leaf(root)
        return self._extract_solution(best_leaf)

    def _select(self, node: LATSNode) -> LATSNode:
        """选择 UCT 分数最高的叶子节点"""
        current = node
        while current.children:
            current = max(current.children, key=lambda n: n.uct_score())
        return current

    def _expand(self, node: LATSNode, problem: str) -> List[LATSNode]:
        """LLM 生成多个候选行动"""
        # 获取祖先反思
        reflections = self._get_ancestor_reflections(node)

        prompt = f"""问题: {problem}

当前状态: {node.state}
历史反思: {reflections if reflections else "无"}

请提出 {self.max_children} 个不同的下一步行动。
每个行动可以是:
- 一个推理步骤（Thought）
- 一个工具调用（Action: tool_name(input)）
- 一个结论（Finish: answer）

输出格式（每行一个）:
1. 行动1
2. 行动2
3. 行动3"""

        response = self.llm.invoke([HumanMessage(content=prompt)])
        actions = parse_numbered_list(response.content)

        children = []
        for action in actions[:self.max_children]:
            child = LATSNode(
                state=f"{node.state}\n→ {action}",
                action=action,
                parent=node,
                depth=node.depth + 1
            )
            # LLM 先验评分
            child.prior_score = self._get_prior_score(problem, child.state)
            node.children.append(child)
            children.append(child)

        return children

    def _simulate(self, node: LATSNode, problem: str) -> float:
        """执行行动并评估"""
        action = node.action

        # 如果是工具调用
        if action.startswith("Action:"):
            tool_call = parse_tool_call(action)
            try:
                result = self.tools[tool_call["name"]].invoke(tool_call["input"])
                node.environment_feedback = str(result)
                node.state += f"\n  结果: {result}"
            except Exception as e:
                node.environment_feedback = f"错误: {e}"
                return 0.1  # 低分

        # 如果是最终答案
        if action.startswith("Finish:"):
            node.is_terminal = True
            # LLM 评估答案质量
            return self._evaluate_solution(problem, action[7:].strip())

        # LLM 评估当前状态价值
        return self._evaluate_state(problem, node.state)

    def _backpropagate(self, node: LATSNode, value: float):
        """回传价值并生成反思"""
        current = node
        while current:
            current.visit_count += 1
            current.total_value += value

            # 如果价值低，生成反思
            if value < 0.3 and current.children:
                current.reflection = self._generate_reflection(current, value)

            current = current.parent

    def _generate_reflection(self, node: LATSNode, value: float) -> str:
        """生成语言化反思"""
        prompt = f"""以下推理路径的评估结果较差（分数: {value:.2f}）:

{node.state}

请简要反思为什么这条路径不好，以及应该避免什么（2-3句话）。"""

        response = self.llm.invoke([HumanMessage(content=prompt)])
        return response.content

    def _evaluate_state(self, problem: str, state: str) -> float:
        """LLM 评估当前状态价值"""
        prompt = f"""评估以下推理状态解决问题的前景（0-100分）。

问题: {problem}
当前推理: {state}

只输出一个数字。"""

        response = self.llm.invoke([HumanMessage(content=prompt)])
        try:
            return float(response.content.strip()) / 100.0
        except:
            return 0.5

    def _evaluate_solution(self, problem: str, answer: str) -> float:
        """评估最终答案"""
        prompt = f"""评估答案是否正确（0-100分）。

问题: {problem}
答案: {answer}

只输出一个数字。"""

        response = self.llm.invoke([HumanMessage(content=prompt)])
        try:
            return float(response.content.strip()) / 100.0
        except:
            return 0.5

    def _get_ancestor_reflections(self, node: LATSNode) -> str:
        """收集祖先节点的反思"""
        reflections = []
        current = node
        while current:
            if current.reflection:
                reflections.append(current.reflection)
            current = current.parent
        return "\n".join(reversed(reflections))

    def _get_best_leaf(self, node: LATSNode) -> LATSNode:
        """找到最佳叶子节点"""
        if not node.children:
            return node
        return max(
            (self._get_best_leaf(c) for c in node.children),
            key=lambda n: n.avg_value
        )

    def _extract_solution(self, node: LATSNode) -> str:
        """提取解决方案路径"""
        path = []
        current = node
        while current.parent:
            path.append(current.action)
            current = current.parent
        return "\n".join(reversed(path))

    def _is_solution(self, node: LATSNode) -> bool:
        return node.is_terminal and node.avg_value > 0.8

    def _get_prior_score(self, problem: str, state: str) -> float:
        return 0.5  # 简化: 等先验

8. LATS 的独特优势

  1. 统一框架: 同时支持推理、行动和规划
  2. 环境反馈: 不仅靠 LLM 自评，还从真实环境获取反馈
  3. 反思驱动: 失败路径生成反思，指导后续搜索
  4. 自适应探索: UCT 平衡利用已知好路径 vs 探索新路径
  5. 可扩展: 可添加任意工具和环境

9. 适用场景

最适合 LATS:
  🔬 科学推理: 需要假设-验证循环
  🧮 数学证明: 需要探索多条证明路径
  🎮 博弈决策: 搜索空间大，需要评估
  🔍 复杂问答: 需要多步工具调用 + 验证
  📝 代码调试: 尝试-反馈-反思循环

不适合 LATS:
  ❌ 简单任务（杀鸡用牛刀）
  ❌ 实时对话（延迟不可接受）
  ❌ 无环境反馈的任务（退化为 ToT）

11. 优化建议

  1. 限制树大小: 设置最大节点数防止内存爆炸
  2. 并行模拟: 多个子节点可并行评估
  3. 缓存: 相同状态的评估结果缓存
  4. 早停: 连续 N 次无提升则停止
  5. 温度控制: 扩展时高温度（探索），评估时低温度（稳定）

落地实践

场景一：评论监控的智能决策

用 LATS 的 MCTS 搜索最优评论处理策略：Selection 选择最有价值的评论 → Expansion 生成多种处理方案 → Simulation 执行并评估效果 → Backpropagation 更新策略。

对于特别复杂的任务（如跨多个知识库的综合分析），LATS 可以帮助 Hermes 探索多条分析路径，结合环境反馈选择最优方案。
