NLP概述与技术演进

来源: 尚硅谷大模型技术之NLP教程 V1.0.3 / 黑马NLP课程 整理时间: 2026-05-30

核心概念

自然语言处理（Natural Language Processing, NLP）是人工智能的重要分支，目标是让计算机"理解"和"使用"人类日常语言。

NLP常见任务

任务类型说明典型应用
文本分类对整段文本进行归类情感分析、垃圾邮件识别、新闻分类
序列标注对每个词/字打标签命名实体识别（NER）、词性标注
文本生成根据输入生成新文本自动写作、摘要生成、对话系统
信息抽取从文本提取结构化信息问答系统、知识图谱构建
文本转换将文本转换为另一种形式机器翻译、文本摘要

技术演进历史

1. 规则系统阶段（50年代-80年代初）

依赖人工编写的语言规则
代表：Georgetown-IBM实验（1954，俄英翻译）、ELIZA聊天机器人（1966）
局限：缺乏通用性，扩展性差

2. 统计方法阶段（90年代）

基于概率建模，从"专家经验"转向"数据驱动"
典型方法：N-gram模型、隐马尔可夫模型（HMM）、最大熵模型
N-gram模型：一个词出现的概率只取决于前面 N-1 个词
Bigram（2-gram）：只考虑前1个词
Trigram（3-gram）：考虑前2个词

3. 机器学习阶段（21世纪初）

引入传统ML方法：逻辑回归、SVM、决策树、CRF
特征工程成为关键环节
词袋模型 + 逻辑回归的文本分类是典型范式

4. 深度学习阶段（2010年代至今）

神经网络取代手工特征工程
关键模型演进：RNN → LSTM/GRU → Transformer → 预训练模型（GPT/BERT）
推动了迁移学习和预训练语言模型的发展

传统序列模型RNN

来源: 尚硅谷大模型技术之NLP教程 V1.0.3 整理时间: 2026-05-30

全局定位

所属知识域：AI大模型 > NLP基础
核心主题：RNN/LSTM/GRU等传统序列模型原理与演进
前置依赖：深度学习基础、NLP概述
关联技能：Transformer、序列建模
应用场景：理解Transformer前序知识、NLP面试

核心概念

RNN（Recurrent Neural Network，循环神经网络）是处理序列数据的经典模型，通过循环连接逐个读取词语，在每步结合当前词和前面的上下文信息，持续建模上下文语义。

注意：RNN已逐渐被Transformer取代，但其"循环建模上下文"的思想是理解LSTM、GRU和Transformer的基础。

RNN基础结构

以时间步（time step）为单位依次处理序列
每步接收：当前token向量 + 上一步隐藏状态 → 生成新隐藏状态 → 传递到下一步
隐藏层计算：h_t = \tanh(x_t W_x + h_{t-1} W_h + b)

RNN结构变体

1. 多层RNN

多个RNN层堆叠，每层输出作为下层输入
底层捕捉局部模式（词组、短语），高层学习抽象语义（主题、语境）

2. 双向RNN

正向RNN（从前到后）+ 反向RNN（从后到前）
每步输出 = 正向和反向隐藏状态的拼接/求和
适用于需要完整上下文的任务（如序列标注、NER）

3. 多层+双向RNN

每层都是双向RNN，组合使用

PyTorch RNN API

"kw">import torch.nn "kw">as nn

rnn = nn.RNN(
    input_size=100,      # 词向量维度
    hidden_size=128,     # 隐藏状态维度
    num_layers=2,        # RNN层数
    batch_first="kw">True,    # 输入shape: (batch, seq, feature)
    bidirectional="kw">True,  # 双向RNN
    dropout=0.1
)

output, h_n = rnn(input, h_0)
# output: 每个时间步的隐藏状态
# h_n: 最后一个时间步的隐藏状态（每层每方向）

RNN的局限性

梯度消失/爆炸：长序列中梯度难以有效传播
长距离依赖困难：难以捕捉序列中远距离的依赖关系
串行计算：无法并行处理，训练效率低

这些局限催生了Transformer的诞生。

LSTM与GRU

LSTM（Long Short-Term Memory）：引入遗忘门、输入门、输出门，有效解决长距离依赖
GRU（Gated Recurrent Unit）：简化版LSTM，参数更少，训练更快

分词与词表构建

来源: 尚硅谷大模型技术之NLP教程 V1.0.3 整理时间: 2026-05-30

全局定位

所属知识域：AI大模型 > NLP基础
核心主题：中文分词算法与词表构建方法，NLP基础技能
前置依赖：Python基础、正则表达式
关联技能：NLP概述、Tokenizer、BPE
应用场景：NLP文本预处理、大模型Tokenizer理解

核心概念

分词（Tokenization）是将原始文本切分为具有独立语义的最小单元（token）的过程，是所有NLP任务的起点。词表（Vocabulary）是模型可识别token的集合，每个token分配唯一ID。

文本表示流程

原始文本 → 分词(Tokenization) → 词表映射(token→ID) → 嵌入层(Embedding) → 词向量

英文分词方法

1. 词级分词（Word-Level）

按空格和标点天然分隔
优点：直观易理解
缺点：OOV（Out-of-Vocabulary）问题——未登录词被替换为 ，丢失语义

2. 字符级分词（Character-Level）

每个字符为一个token
优点：词表极小，几乎无OOV
缺点：单字符语义弱，序列过长，建模难度大

3. 子词级分词（Subword-Level）⭐ 主流方法

将词切分为子词（词根、前缀、后缀等）
缓解OOV，保留语义结构
核心算法：
BPE（Byte Pair Encoding）：迭代合并频率最高的字符对
WordPiece：BERT使用的变体
Unigram Language Model：概率模型选择最优切分
BERT、GPT等模型均采用子词分词

中文分词方法

1. 字符级分词

按单个汉字切分
中文汉字本身具有独立语义，比英文字符分词更"语义友好"
主流中文大模型（通义千问、DeepSeek）广泛采用

2. 词级分词

按完整词语切分，贴近阅读习惯
依赖词典/规则/模型识别词边界（中文无天然空格分隔）

3. 子词级分词

BPE算法直接应用于中文，以汉字为基本单位学习高频字组合
无需人工词典，适应能力强

7.2.3.2 自注意力层

自注意力机制（Self-Attention）是 Transformer 编码器的核心结构之一，它的作用是在

序列内部建立各位置之间的依赖关系，使模型能够为每个位置生成融合全局信息的表示。

之所以被称为“自”注意力，是因为模型在计算每个位置的表示时，所参考的信息全部

来自同一个输入序列本身，而不是来自另一个序列。

1）自注意力计算过程

自注意力的完整计算过程如下：

（1）生成Query、Key、Value向量

自注意力机制的第一步，是将输入序列中的每个位置表示映射为三个不同的向量，分别

是 查询（Query）、键（Key） 和 值（Value）。

这些向量的作用如下：

Query：表示当前词的用于发起注意力匹配的向量；

Key：表示序列中每个位置的内容标识，用于与 Query 进行匹配；

Value：表示该位置携带的信息，用于加权汇总得到新的表示。

自注意力的核心思想是：每个位置用自身的 Query 向量，与整个序列中所有位置的

Key 向量进行相关性计算，从而得到注意力权重，并据此对对应的 Value 向量加权汇总，

形成新的表示。

2）多头自注意力计算过程

自注意力机制通过Query、Key和 Value向量计算每个位置与其他位置之间的依赖关

系，使模型能够有效捕捉序列中的全局信息。

然而，自然语言本身具有高度的语义复杂性，一个句子往往同时包含多种类型的语义关

系。例如，句子“那只动物没有过马路，因为它太累了”中就涉及多个层面的语言关系：

 “它”指代“那只动物”，属于跨句的代指关系；
 “因为”连接前后两个分句，体现语义上的因果逻辑；
 “过马路”构成动词短语，属于固定的动宾结构。

要准确理解这类句子，模型需要同时识别并建模多种层次和类型的依赖关系。但这些信

息很难通过单一视角或一套注意力机制完整捕捉。

为此，Transformer引入了多头注意力机制（Multi-HeadAttention）。其核心思想是通
过多组独立的Query、Key、Value投影，让不同注意力头分别专注于不同的语义关系，最

后将各头的输出拼接融合。

多头注意力的计算过程如下：

（1）分别计算各头注意力

每个 Self-AttentionHead独立计算一套注意力输出。

（2）合并多头注意力

多个输出矩阵按维度拼接，再乘以 得到最终多头注意力的输出。

7.2.3.3 前馈神经网络层

前馈神经网络（Feed-ForwardNetwork，简称FFN）是 Transformer编码器中每个子层

的重要组成部分，紧接在多头注意力子层之后。它通过对每个位置的表示进行逐位置、非线

性的特征变换，进一步提升模型对复杂语义的建模能力。

核心概念

提示词工程（Prompt Engineering）是通过精心设计输入提示，引导大语言模型输出符合预期结果的技术。不改变模型参数，通过调整输入控制输出。

一、角色设定（Role Prompting）

通过在输入中明确指定AI的身份、背景和专业领域，约束输出风格与知识边界。

三要素：你是谁（身份）、你要做什么（任务）、你不能做什么（负面约束）

核心逻辑：缩小模型在概率空间中的搜索范围，从"大海捞针"变为"在专业书架上取书"。

最佳实践

角色设定遵循"关键约束原则"，只保留决定性影响的背景、技能和禁忌
在System Prompt中定义角色，User Prompt中通过指令加固
过长设定会占用Token并导致注意力分散

二、N-Shot Prompting

通过展示0/1/多个示例，引导模型理解任务意图。

方法说明适用场景
Zero-shot直接下指令，无示例通用任务（"总结这篇文章"）
One-shot给1个示例定调子特定格式/风格
Few-shot给3-8个示例特定格式、冷门领域

关键原理

上下文学习（In-Context Learning）：LLM无需微调，仅通过Prompt中的示例即可学习
样本过多会导致"复读机"效应，通常3-8个最佳
与模型微调相比：N-Shot不改模型参数（省钱快），Fine-tuning改参数（贵慢强）

三、思维链（Chain of Thought, CoT）

在Few-shot示例中不仅给出"问题-答案"，还要写出中间推理过程，诱导模型进行逻辑推理。

核心公式

CoT = Few-shot + 逻辑过程

Zero-shot CoT

在Prompt末尾加一句魔法咒语："Let's think step by step"，无需示例即可提升推理准确度。

适用场景

复杂财务计算
代码纠错（分析Bug成因→修复方案）
多步决策（退货流程判断）

重要限制

CoT是涌现能力，通常在70B+参数模型上才有效
小模型（7B）强行CoT可能废话连篇

面试要点

问题回答思路
角色设定越详细越好？过犹不及，遵循关键约束原则
Few-shot越多越好？不是，边际效应递减，3-8个最佳
CoT在小模型有效吗？效果不佳，是涌现能力，需大模型

核心概念

知识图谱（Knowledge Graph）将碎片化信息连接成"实体-关系-实体"的网络，让AI理解谁是谁的谁。基本单位是三元组 (Subject, Predicate, Object)。

知识图谱 vs 向量检索

特性向量检索知识图谱
匹配方式模糊/语义相似精确/逻辑推理
擅长非结构化语义结构化事实
可解释性黑盒路径清晰可追溯
多跳推理弱强（顺藤摸瓜）

核心价值

多跳推理："周杰伦岳母的家乡在哪？" → 周杰伦→妻子→昆凌→母亲→某地
消除幻觉：提供确定性事实，约束LLM输出
可解释性：推理路径清晰可追溯

核心概念

知识蒸馏（Knowledge Distillation）是模型压缩技术，让大模型（Teacher）手把手教小模型（Student），使小模型用更少参数达到接近大模型的水平。

一句话：学生不只是背答案，而是学会老师的思考逻辑。

核心机制

教师-学生架构

Teacher Model (大) → 输出概率分布（软标签/Soft Target）
                        ↓
Student Model (小) → 学习软标签 + 真实标签 → 压缩模型

软标签与暗知识

硬标签（Hard Target）：冷冰冰的0/1标签（"是猫"）
软标签（Soft Target）：各类别的概率分布（"80%猫，15%狗，5%兔"）
暗知识（Dark Knowledge）：软标签中包含的类间关系信息——"虽然答案是猫，但狗也很像"

温度系数（Temperature, T）

用T平滑Softmax输出：p_i = \frac{e^{z_i/T}}{\sum e^{z_j/T}}
T越大，概率分布越平坦，学生学到更多暗知识
T=1即普通Softmax

损失函数

蒸馏损失由两部分组成：

L = \alpha \cdot L_{hard} + (1-\alpha) \cdot T^2 \cdot L_{soft}

L_{hard}：学生预测 vs 真实标签（交叉熵）
L_{soft}：学生输出 vs 教师输出（KL散度）
"kw">import torch.nn.functional "kw">as F

"kw">def distillation_loss(student_out, teacher_out, labels, T=3.0, alpha=0.5):
    soft_teacher = F.softmax(teacher_out / T, dim=1)
    soft_student = F.log_softmax(student_out / T, dim=1)
    loss_soft = F.kl_div(soft_student, soft_teacher, reduction="str">&#x27;batchmean') * (T ** 2)
    loss_hard = F.cross_entropy(student_out, labels)
    "kw">return alpha * loss_hard + (1 - alpha) * loss_soft

场景说明
搜索推荐复杂精排模型蒸馏为轻量模型，毫秒级响应
语音唤醒"Hey Siri"——芯片级小模型学到大模型逻辑

对比其他压缩方法

方法说明特点
蒸馏大模型教小模型学生结构完整密集
剪枝删除不重要的参数/连接结构变稀疏
量化降低参数精度（FP32→INT8）不改变结构

词向量与Word2Vec

来源: 尚硅谷大模型技术之NLP教程 V1.0.3 整理时间: 2026-05-30
## 全局定位 知识领域：AI大模型 → NLP基础 → 词向量表示 在AI知识图谱中的位置：词向量是NLP的基石，从离散符号到连续向量的跨越，为语义理解提供数学基础 上下游关系：上接 分词与词表构建（分词基础），下启 传统序列模型RNN（序列建模）、NLP概述与技术演进（技术演进）
## 知识串联 | 关联主题 | 链接 | 关系 | |----------|------|------| | 分词基础 | 分词与词表构建 | 词向量的输入依赖分词 | | RNN | 传统序列模型RNN | 词向量作为RNN输入 | | NLP概述 | NLP概述与技术演进 | 词表示技术演进路线 | | 提示词工程 | 提示词工程核心技巧 | 语义理解基础 | | 知识蒸馏 | 知识蒸馏 | 模型压缩中的词向量传递 |
## 落地实践 - 核心概念：将token转换为稠密向量，One-hot→Word2Vec→ELMo/BERT演进 - AI项目应用： - Word2Vec(CBOW/Skip-gram)：快速训练领域词向量 - 余弦相似度：计算词与词的语义距离 - 词向量迁移：预训练词向量加速下游任务收敛 - 面试话术：「词向量解决了one-hot编码无法表达语义关系的问题，Word2Vec通过上下文窗口学习分布式表示，使语义相近的词在向量空间中距离也相近」
## 难度标识 - 难度等级：⭐⭐⭐☆☆ (3/5) - 前置要求：线性代数基础、概率论基础 - 面试频率：☆ — NLP岗必考基础

核心概念

词表示（Word Representation）是将token转换为计算机可处理的数值形式。发展路径：One-hot编码 → 语义化词向量（Word2Vec） → 上下文相关词表示（ELMo/BERT）。

One-hot编码

每个词映射为长度等于词表大小的稀疏向量，该词位置为1，其余为0
缺点：无法体现词与词之间的语义关系；维度随词表膨胀

Word2Vec

核心思想

基于分布假设——一个词的含义由它周围的词决定。

两种模型结构

模型输入目标特点
CBOW上下文词（前后若干词）预测中间目标词训练快，适合高频词
Skip-gram中心词预测上下文词适合低频词，语义更丰富

Skip-gram 前向传播

输入中心词（one-hot）→ 与 W_{in} 相乘 → 取出词向量
词向量与 W_{out} 相乘 → 得分
Softmax → 概率分布
与真实上下文比较 → 交叉熵损失
反向传播更新 W_{in} 中对应词向量

CBOW 前向传播

输入多个上下文词 → 分别与 W_{in} 相乘 → 取出词向量
上下文词向量取平均
平均向量与 W_{out} 相乘 → Softmax → 预测中心词
计算损失 → 反向传播

上下文相关词表示

问题：Word2Vec是静态词向量——"苹果"在不同语境中向量相同
解决方案：上下文相关词表示（Contextual Word Representations）
代表模型：ELMo（2018）——基于LSTM语言模型，动态生成每个词的表示
词向量由前文和后文共同决定，是首个广泛应用于下游任务的上下文词向量

余弦相似度

similarity(w_1, w_2) = \cos(\theta) = \frac{\vec{w_1} \cdot \vec{w_2}}{||\vec{w_1}|| \cdot ||\vec{w_2}||}

接近1：高度相似
接近0：无明显相关
接近-1：极度不相似
