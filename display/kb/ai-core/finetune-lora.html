LoRA 概述

一、核心概念

LoRA（Low-Rank Adaptation） 是一种高效参数微调技术，基于"权重变化矩阵具有低内在维度"的洞察。

一句话结论：在冻结原模型参数的前提下，通过外挂两个极小的低秩矩阵补丁，实现低成本的高效微调。

生活类比：想象你有一台不可改装的赛车（预训练模型）。为了适应沙漠赛道，你并没有拆开引擎重新打磨，而是在方向盘和档位上加装了一套"沙漠辅助遥控器"（LoRA）。

二、核心原理

2.1 数学表示

  • 预训练权重矩阵：W₀ (d × k)
  • 全参数微调后：W = W₀ + ΔW
  • LoRA将ΔW表示为两个低秩矩阵的乘积：ΔW = B × A
  • A ∈ ℝ^(r×k)，降维矩阵
  • B ∈ ℝ^(d×r)，升维矩阵
  • r << min(d,k)，通常r=8或16

    • 前向传播：

    h = W₀·x + (α/r)·(B·A·x)

    2.2 初始化方式（关键）

  • A矩阵：随机正态分布初始化 N(0, σ²)
  • B矩阵：全零初始化
  • 让LoRA支路训练初期输出为0，不影响原模型

    • 2.3 缩放系数

    代码实现引入额外参数 α（lora_alpha），控制低秩矩阵对激活值的影响程度：

    输出 = W₀·x + (α/r)·(B·A·x)

    低秩分解图示

    下图展示了 LoRA 的核心机制：在冻结的预训练权重 W₀ 旁并行注入两个低秩矩阵 A (降维) 和 B (升维)，通过 h = W₀x + (α/r)·BAx 实现高效微调。

    LoRA 最佳实践与对比

    三、参数量优势

    以BERT-base为例：

  • 原Attention层 W (768×768) = 58.9万参数
  • LoRA (r=8) 仅 A(768×8) + B(8×768) = 1.2万参数
  • 参数量减少98%

    • 以GPT-3 175B为例：

  • 全参微调检查点：350GB
  • LoRA (r=2, 仅适配Q和V)：35MB（万分之一）

    • 四、推理阶段处理

    方式一：合并权重（零延迟推理）

    W_new = W₀ + B × A

    合并后模型结构与原模型完全一致，无额外推理延迟。

    方式二：不合并（动态切换）

  • 分别存储W₀和AB，推理时分别计算后求和
  • 引入少量延迟，但可动态替换AB实现多任务切换

    • 五、最佳实践

    5.1 应用哪些权重矩阵

  • 同时适配Q和V矩阵效果最佳（参数预算固定时）
  • 用更小的秩适配更多矩阵 > 用更大秩适配单个矩阵
  • Qwen3推荐：["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"]

    • 5.2 秩(r)的选择

  • 通常选8或16，简单任务r=4即可
  • 同时适配多矩阵时，只需很小的秩(r=2)即可获得最佳性能
  • 复杂任务可提升至r=32-64

    • 5.3 超参数推荐

    参数推荐值说明
    r8-32简单任务8，复杂任务32-64
    lora_alphar 或 2×r避免>128
    lora_dropout0-0.3小数据集用0.1-0.3
    target_modulesq,v,o,k + FFN层覆盖越广效果越好
    bias"none"通常关闭

    六、LoRA vs 全量微调

    对比维度LoRA全量微调
    参数量0.1~1%100%
    显存占用降低60%-80%极高
    训练速度更快（无需计算冻结参数梯度）较慢
    效果接近全参微调最好
    多任务支持热插拔AB矩阵需存储多个完整模型
    灾难性遗忘有效防止可能发生

    八、面试高频问题

    Q1：LoRA的Rank参数选多大？

    并非越大越好。Rank通常选8或16。增加Rank提高拟合能力但增加显存；简单任务Rank=4即可。

    Q2：为什么LoRA不会增加推理延迟？

    矩阵乘法具有分配律，部署阶段可预先将A和B的乘积加回到W₀中，合并后与原模型一致。

    Q3：LoRA只适用于Transformer的Attention层吗？

    理论上可用于任何线性层，实操中通常应用在Query/Value矩阵上，因为这是捕捉任务特征最有效的地方。

    LoRA 代码示例

    七、代码示例

    7.1 使用PEFT库

    from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

# 1. 加载基础模型
model = AutoModelForCausalLM.from_pretrained("facebook/opt-350m")

# 2. 定义LoRA配置
config = LoraConfig(
    r=8,                          # 秩大小
    lora_alpha=32,                # 缩放系数
    target_modules=["q_proj", "v_proj"],  # 作用于Q和V
    lora_dropout=0.1,
    task_type="CAUSAL_LM"
)

# 3. 注入LoRA补丁
lora_model = get_peft_model(model, config)

# 4. 验证：仅显示可训练参数
lora_model.print_trainable_parameters()
# 输出: trainable params: 786,432 || all params: 331,182,080 || trainable%: 0.2374

    7.2 使用Unsloth（推荐）

    from unsloth import FastLanguageModel

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Qwen3-8B-unsloth-bnb-4bit",
    max_seq_length=2048,
    load_in_4bit=True,
)

model = FastLanguageModel.get_peft_model(
    model,
    r=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
    lora_alpha=32,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing="unsloth",  # 节省30%显存
    random_state=3407,
)

    QLoRA 概述

    一、核心概念

    QLoRA（Quantized Low-Rank Adaptation） = 4-bit量化 + LoRA低秩适配器

    一句话总结：通过4-bit量化把模型压缩得极小，再在压缩模型上贴LoRA补丁，让极低配置的显存也能微调超大型模型。

    大白话：

  • 量化(Q)：把高清电影压缩成480P，模型权重从16位浮点压缩为4位
  • LoRA：模型主体权重锁死，在旁边开辟一个小笔记本（旁路矩阵）
  • QLoRA组合技：把模型压扁放进显存，然后把"笔记本"贴在它身上

    • 三、存在意义

    场景全量微调QLoRA
    Llama 3 (70B) 显存需求1TB+~48GB
    硬件成本几百万元几张消费级显卡
    微调效果最好接近全量微调

    核心价值：

  • 显存危机救星：消费级显卡（如RTX 4090）也能微调70B模型
  • NF4格式保证模型被压扁后"智商"几乎不下降
  • 双重量化把压榨显存做到极致

    • 三大核心技术

    二、三大核心技术

    2.1 NF4（4-bit NormalFloat）

  • 一种对以零为中心的正态分布数据信息论上最优的数据类型
  • 比4-bit int和4-bit float效果更好
  • 原理：利用标准正态分布的分位数函数创建非对称数据类型
  • 将[-1, 0]分成7份 → 8个分位数
  • 将[0, 1]分成8份 → 9个分位数
  • 合并去重得到16个分位数（4-bit）
  • 每个量化bin中有相等期望值数量的数据

    • 2.2 双重量化（Double Quantization）

  • 量化过程中每64个参数共享一个量化常数（Absmax, 32bit）
  • 每参数额外开销：32bit/64 = 0.5bit
  • 二次量化：用256块大小对量化常数进行FP8量化
  • 优化后每参数额外开销：8/64 + 32/(64×256) = 0.127 bit

    • 2.3 分页优化器（Paged Optimizers）

  • GPU内存不足时，自动将优化器状态卸载到CPU RAM
  • 需要时再分页回GPU内存
  • 类似CPU RAM和磁盘之间的常规内存分页
  • 避免GPU OOM

    • LoRA vs QLoRA 对比

    四、LoRA vs QLoRA

    对比维度LoRAQLoRA
    基座模型精度16-bit4-bit NF4
    AB矩阵精度高精度高精度（不变）
    显存占用低更低
    训练速度快稍慢（需反量化）
    效果接近全参略低于LoRA
    适用场景显存充足显存紧张首选

    关键区别：QLoRA是对基座模型做4-bit NF4量化，AB矩阵仍保持高精度。

    五、为什么QLoRA训练比LoRA慢？

    因为"反量化"过程：每次计算梯度时，系统要把4-bit权重还原成16-bit才能参与运算，这个转换过程需要额外的计算周期。

    QLoRA 代码示例

    六、代码示例

    import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# 1. 配置4-bit量化（QLoRA核心设置）
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,      # 双重量化：更省显存
    bnb_4bit_quant_type="nf4",           # NF4格式：保证精度
    bnb_4bit_compute_dtype=torch.bfloat16 # 计算时临时转回bfloat16
)

# 2. 加载被"压缩"的模型
model = AutoModelForCausalLM.from_pretrained(
    "shibing624/llama-7b-zh",
    quantization_config=bnb_config
)

# 3. 为量化微调做准备
model = prepare_model_for_kbit_training(model)

# 4. 配置LoRA"补丁"
lora_config = LoraConfig(
    r=8,
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

# 5. 组合模型
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 可训练参数占比通常不到1%

    • LLaMA-Factory 使用指南

    一、LLaMA-Factory 是什么

    LLaMA-Factory 是一个零代码/低代码的大模型微调框架，提供从数据预处理、模型训练（SFT/RLHF/DPO）到评估导出的一站式图形化界面。

    核心价值：

  • 全球最流行、支持模型最全（100+模型）的开源微调框架
  • 统一了上百种模型的微调接口
  • 集成LoRA/QLoRA等省显存技术，8G显存也能玩微调
  • 复杂分布式训练封装为简单YAML配置

    • 二、快速启动

    git clone --depth 1 https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e .[torch,metrics]

    九、核心思想

    LLaMA-Factory微调的核心不是"训模型"，而是：用结构化数据，稳定地改变模型判断行为。

    十、面试要点

    Q1：为什么推荐LoRA而不是全参微调？

    关键词：资源消耗 + 灾难性遗忘。LoRA只训练极少量参数，保护原模型"智商"，普通显卡就能跑。

    Q2：Loss一直不下降怎么排查？

    检查数据格式（指令字段是否正确识别）、学习率（是否太大导致震荡）、Prompt Template（模版选对了吗）。
